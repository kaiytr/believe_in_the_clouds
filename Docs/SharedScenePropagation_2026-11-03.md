# 전체 씬 공통 기능 적용 · 2026-11-03

## 범위와 기준

기준 Puri는 `54947fe`, Leesc는 `9416972`다. Puri에 병합된 Leesc의 공격·재단·상점·HUD 변경을 프로젝트 씬 14개에서 사용할 수 있도록 연결과 설정을 점검했다. Gameplay 7개, Tests 4개, Sources 3개가 대상이며 플레이어가 없는 URP 새 씬 템플릿은 제외한다.

플레이어와 HUD 기준은 다음 프리팹이다.

- `Assets/Prefabs/Player/Player.prefab`
- `Assets/Prefabs/UI/PlayerHud.prefab`

## 발견한 누락과 보완

| 씬 | 이전 상태 | 보완 |
| --- | --- | --- |
| Gameplay/ShopTest | 독립 플레이어 복사본에 과거 공격 값이 남고 HUD는 런타임 생성에 의존 | 공통 플레이어·HUD 프리팹 연결 |
| Sources/EnemyTest | 단순 더미 플레이어에 공통 공격 구성이 없고 HUD 미배치 | 공통 플레이어·HUD 프리팹 연결 |
| Tests/FoundationTest | 공통 플레이어를 쓰지만 HUD 미배치 | 공통 HUD 프리팹 배치 |
| 나머지 11개 씬 | 이미 공통 플레이어·HUD 프리팹 사용 | 상속된 최신 공격 설정과 참조 전수 확인 |

기존 플레이어를 교체할 때 발 위치, 카메라 타깃, 더미 피격 도구와 외부 컴포넌트 참조를 이어 주었다. 씬 GUID와 맵 배치는 유지한다. 수정이 필요했던 씬 파일은 3개이며 나머지는 공통 프리팹 변경을 상속한다.

공통 플레이어에는 `DoctrineSubject.Identity = Player`를 지정했다. 이 설정이 없어 플레이어를 소유자로 지정하는 교리 등록이 거부되던 경로를 보완했다. 공중 공격의 인스펙터 이름도 실제 아래 부채꼴 동작에 맞췄다.

HUD는 소유자인 GameObject를 PlayerHealth 컴포넌트와 비교해 플레이어 소유 교리를 제외하던 오류를 고쳤다. 교리 설명은 별도 Canvas 순서 160을 사용하여 HUD·테스트 패널·코인보다 앞, 상점·재단 모달보다 뒤에 표시한다. 설명은 3초 표시 후 0.5초 동안 사라진다.

이미 Canvas가 있는 프리팹 HUD에서도 GraphicRaycaster를 준비하도록 보완했다. 이전에는 Canvas를 새로 만드는 분기 안에서만 추가하여 프리팹의 슬롯 버튼에 마우스 클릭이 전달되지 않을 수 있었다.

상점·재단·교리칸 저장소는 기존 공통 런타임 부팅을 사용한다. 각 씬에서 하나씩 생성되는지 실제 PlayMode로 확인한다. 교리칸의 앱 재시작 저장 정책은 [기존 통합 기록](LeescMergeIntegration_2026-11-03.md)에 명시되어 있다.

## 다시 동기화하는 방법

1. 공통 공격 설정은 Player 프리팹에서 수정한다.
2. `Tools > Project > Sync shared player and UI in all scenes`를 실행한다.
3. `Audit shared scene setup`으로 연결 상태를 확인한다.

동기화는 독립 플레이어 교체, 공격 설정의 씬별 덮어쓰기 해제, 공통 HUD 단일 배치, Cinemachine 가로 추적과 보스전 이후 고정 높이 복귀를 처리한다. 정상 씬은 다시 저장하지 않는다. 재실행 검사에서 추가 변경은 0개였다.

상점·단독 전투·신앙·보스·스테이지·런 연결 생성 도구에도 동기화를 연결했다. 생성 도구를 실행한 뒤에도 공통 프리팹 설정과 가로 카메라 구성을 사용한다.

## 검증 내용

- EditMode: 14개 씬 각각의 공통 프리팹 연결, 공격 수치·부채꼴 설정, Player 교리 주체, HUD 단일 배치, 카메라·더미 도구 참조를 검사한다.
- PlayMode: 14개 씬을 순서대로 열어 공통 플레이어·상점·재단·교리칸 저장소·HUD가 하나씩 존재하는지 확인한다. 각 씬에서 플레이어 소유 교리를 등록하고 슬롯 중앙 화면 좌표로 EventSystem 레이캐스트와 포인터 클릭을 전달해 설명을 연다. 다른 UI가 슬롯을 가리지 않는지도 확인한다.
- ShopTest에서는 설명의 표시 기간과 페이드 후 숨김을 확인한다. ShopTest·EconomyTest·EnemyTest의 설명 표시 화면도 캡처한다.
- 기존 일반 전투·보스·상자·재화·로비 흐름과 공중 공격 적중·반동·착지 후 재사용을 함께 확인한다.

Unity 6000.3.5f2의 별도 프로젝트 복사본에서 실행한다. 원래 열려 있던 Unity 편집기는 유지한다. XML·로그·화면 캡처·씬 동기화 보고서는 `Logs/ScenePropagation_2026-11-03/`에 보관한다.

마지막 단일 케이스는 프로젝트 씬 14개를 모두 순회한다. 포인터 검사의 유일한 실패는 슬롯이 생성된 프레임에 CanvasRenderer가 아직 레이캐스트 목록에 등록되지 않은 준비 시점 문제였다. 한 프레임 렌더링 후 실제 포인터 클릭을 검사하도록 보완했고 14개 씬 모두 통과했다. 케이스별 최신 PlayMode 결과는 **104개 통과, 미해결 실패 0개**이며 마지막 보완 후 전체 PlayMode를 한 번에 재실행한 결과와는 구분한다.

최종 씬 감사는 14/14 정상, 재실행 변경 0개였다. 버전 관리 대상 Assets의 최종 해시는 검증 복사본과 모두 일치했다. ShopTest·EconomyTest·EnemyTest의 설명 표시 캡처를 확인했고 임시 검증 프로젝트는 결과 보관 후 정리한다.

## 브랜치 반영

Puri에서 검증한 변경을 커밋한 뒤 Leesc를 해당 Puri 커밋으로 fast-forward한다. 두 브랜치는 같은 검증 상태를 가리키도록 원격에 함께 반영한다.
