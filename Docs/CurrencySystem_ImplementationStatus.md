# 재화 시스템 구현 결과

작업일: **2026-11-01 (Asia/Seoul)** · Unity **6000.3.5f2**

사용자의 `CurrencySystem_Handoff.md` 기반 구현 시작 지시에 따라 **테스트 씬에서 독립 검증하는 재화 시스템**을 구현했다. 실제 로비·분기·스테이지 진행·이어 하기·엔딩·재단 전체는 연결하지 않았다.

후속 업데이트: [로비 구현 결과](LobbySystem_ImplementationStatus.md)에 따라 로비·분기·임시 스테이지 왕복과 임시 런 이어하기를 연결했다. 경제 프로필은 v1 자산을 보존하는 schemaVersion 2로 확장했다. 아래 독립 재화 검증 결과는 최초 재화 작업의 기록이며, 현재 전체 테스트 결과는 로비 결과서를 참조한다.

## API·데이터의 구체화

- 구매 반환형은 `CurrencyResult`로 통일했다. `Currency.Service.TryPurchase(new PurchaseRequest(cardIds, transactionId))`를 호출한다.
- 조각은 세 enum 인덱스 배열 대신 안정적 카드 ID와 수량인 `pieces[]`로 저장한다. 비어 있는 `ResultType=3`을 잘못 인덱싱하지 않는다.
- 장착 어댑터는 원장에 이미 포함된 원본 조각을 참조한다. 해제 시 조각을 다시 더하지 않는다. 실제 재단의 가용량/예약량 모델은 추후 이 계약으로 연결한다.
- `Snapshot()`은 깊은 복사다. `Changed`·`DeathCompleted`는 커밋 뒤에 발행한다. 이벤트 오류가 저장 성공을 취소하거나 거래를 재실행하지 않는다.
- 사망 저널의 영속 단계는 Captured / LossPrepared / Committed다. 효과 처리·전체 해제는 실행 중 한 번 수행하며 재실행 복구에서는 전투 효과를 재생하지 않는다. 원래 전투 전체의 복원은 후속 범위다.
- Unity JSON의 인라인 null 직렬화를 구분하기 위해 `hasDeath`를 저장한다. 빈 신규 프로필이 사망 처리로 오인되지 않게 한다.
- 고정 경제 규칙의 출처는 `EconomySettings`의 상수와 드롭 추첨 메서드다. `Assets/Resources/EconomySettings.asset`은 시간·크기·색상·표시 수 등 연출 설정을 제공한다.

## 검증 결과

최종 전체 실행은 **164개 전부 통과**, 실패·스킵 0개다.

**2026-11-01 사용자 수동 검증 완료:** 제공한 테스트 항목을 사용자가 직접 확인했고 모두 정상 작동한다고 보고했다. 자동 테스트와 사용자 확인을 합쳐 현재의 테스트 씬 독립 검증 범위는 완료로 정리한다. 별도 실행 파일의 배포 환경 검증까지 수행한 것으로 확대하지 않는다.

기존 교리·믿음·보스·상호작용·StageIntegration 회귀 테스트도 포함했다. 동시 64개 제한·208코인 묶음 보상·저장 실패 후 도착 재시도·실제 보스 무보상·처치 접수 실패 재시도와 사망 이후 차단도 검증했다.

전체 회귀 검증 중 기존 보스 테스트가 후속 공격의 무작위 선택에도 투사체만 기다리는 문제를 확인했다. `DistantAttackAndDodgeUsesProjectileAndCountsMovementEvade`의 테스트 선택 풀을 투사체로 고정했다. 실제 보스의 공격 선택 규칙은 변경하지 않았다.

## 실행과 제한

`Assets/Scenes/Tests/EconomyTest.unity`를 열어 Play한다. [테스트 가이드](CurrencySystem_TestGuide.md)에 버튼과 저장 경로를 기록했다. 새 씬은 `Tools > Economy > Build independent test scene`으로 재생성할 수 있다.

StageTest의 R 재시작은 씬만 재생성하며 사망 손실을 추가 적용하지 않는다. 현재 실제 적은 생성 시 새 처치 ID를 갖는다. 테스트 API는 안정적인 테스트 ID의 저장·중복 요청을 검증한다. 실제 적 생사·HP·위치·스폰 ID를 경제와 함께 저장하는 전체 이어 하기는 후속 메인 루프 작업이다.

경제 프로필은 코인·조각·대기 보상·거래 결과·사망 저널을 복원한다. 장착 테스트 자료를 실제 신규 지급으로 사용하지 않으며, 손실 뒤 이전 조합을 자동 복원하지 않는다. 사망 완료 이벤트 이후 실제 로비 전환과 재단 연동은 이번 구현에 포함하지 않는다.

## 남은 작업 (사용자 수동 검증 후)

현재 독립 검증 범위에서 확인된 미해결 오류는 없다. 아래는 실제 게임 연결과 배포 전 확인을 위한 후속 작업이며, 이번 정리에서 기능 개발을 추가로 시작하지 않는다.

| 구분 | 남은 작업 | 완료 기준 / 연결 시점 |
| --- | --- | --- |
| 실제 재단·장착 연결 | 테스트 장착 어댑터를 실제 조합·장착·해제·슬롯 상태와 연결. 소유량과 장착에 참조된 수량을 구분 | 같은 원본 조각이 중복 사용·중복 반환되지 않고 사망 시 실제 장착·효과가 전부 정리됨. 재단 개발 시 진행 |
| 진행과 경제 통합 저장 | 위치·HP·적 생사·스테이지 진행·장착 연결을 경제 프로필과 같은 저장 시점에 확정 | 종료/재개 뒤 처치한 적과 그 보상이 일치하고 구매·장착 결과가 함께 복원됨. 메인 루프 저장 조정기 개발 시 진행 |
| 영속 처치·생명 ID | 현재 생성 시 GUID를 실제 stageInstanceId/spawnId와 저장된 생명/사망 ID로 연결 | 같은 진행을 다시 불러와도 처치 보상·사망 손실이 추가 적용되지 않음. 통합 저장과 함께 진행 |
| 사망 후 실제 전환 | DeathCompleted를 로비 복귀·후속 진행 처리에 연결 | 손실 저장 성공 후 한 번만 전환하고 실패/재시도 중에는 전환하지 않음. 로비·메인 루프 개발 시 진행 |
| 빌드 환경 검증 | Editor 밖 실행 파일에서 실제 저장 경로·종료/재실행·비행 중 종료·사망 저장 중 중단·백업 복구를 확인 | 경제 자산의 누락·중복 없이 복원됨. 지금까지의 메모리/격리 파일 자동 테스트와 사용자 씬 검증에 추가하는 배포 전 확인 |
| 저장 상태 안내 | 정상 로딩·저장 실패·손상본·미지원 버전·백업 복구를 구분해 안내하고 허용된 복구/재시도 흐름 연결 | 현재의 일반적인 ‘재화 확인 중’ 표시에서 원인과 가능한 조치를 알 수 있음. 실제 게임 UI 정리 시 진행 |
| 콘텐츠 결정 | 엔딩 후 자산 초기화/계승, 실제 스테이지 보상 구성·적 수, 첫 구매/조합 목표 시간 결정 | 실제 콘텐츠를 기준으로 확정. 현재 드롭·가격·손실률은 기존 확정 규칙을 유지 |

추가 개선 후보는 거래 이력이 누적되는 장시간 플레이에서 저장 파일 크기·거래/도착 저장 시간 확인, 사운드·획득 피드백 조정이다. 성능 최적화나 연출 변경은 확인 결과에 따라 진행하며 현재 기능의 미완료 항목으로 취급하지 않는다.

후속 구현 순서는 **실제 재단 연결 → 메인 루프의 영속 ID·통합 저장·사망 복귀 연결 → 실제 진행을 포함한 빌드 검증**을 제안한다. 경제 단독 빌드의 저장/종료 검증은 재단·메인 루프와 별도로 먼저 수행할 수 있다.
