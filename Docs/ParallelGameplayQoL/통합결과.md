## 최종 기능

1. 새로 산정하는 상자·몬스터 코인 보상은 기존 추첨 결과의 두 배다. 기존 V1 상자 계획·영수증은 유지하고 새 상자는 V2를 사용한다. 보스 보상 0, 가격·사망 손실·교리 조각 지급 규칙은 유지한다.
2. 대시 이동이 끝나도 대시 소유 무적만 0.10초 더 유지한다. 이동 잠금은 원래 시점에 해제한다.
3. 일반 몬스터와 보스는 플레이어가 반대편에 약 0.5초 머무르면 방향을 바꾼다. 공격 예고와 실제 방향을 맞추도록 방향 확정 후 공격을 시작한다.
4. F2 도구에 최대 체력 회복·보스 해금 조건 달성·로비 분기 리롤과 상태/결과 표시를 추가했다. 리롤은 런·생명·클리어·방문·자산·장착을 유지하고 후보 ID만 새로 생성한 뒤 로비를 재로드한다.
5. 클릭한 교리 설명 제목은 `교리1`처럼 번호만 표시한다. 설명 본문·실제 효과·슬롯 내부 요약은 유지한다.

세션별 상세 구현·정책은 같은 폴더의 A/B/C 인계 문서를 참고한다.

## 통합 검증

- Unity 6000.3.5f2의 기존 컴파일 응답 파일·참조 어셈블리와 Roslyn으로 통합 런타임, 에디터, EditMode 테스트 어셈블리 코드를 컴파일했다. 컴파일 오류가 없었다.
- 전체 Unity Editor 실행·Library 임포트·빌드 및 EditMode/PlayMode 테스트 실행은 하지 않았다. 테스트 어셈블리 컴파일과 테스트 실행은 구분한다.
- 실제 통합 서비스 소스를 이용한 관리형 하네스의 거래 검증 7개를 통과했다: 해금 진행 보존·멱등성, 높은 클리어 수 보존, 리롤 진행값/공개 결제 보존, 저장 실패 및 동일 추첨 재시도, 낡은 요청·스테이지 탈출 거부, 해금 저장 실패 원자성, 대기 코인 보존.
- A/C 교차 연결을 추가 확인했다: V1 상자 열기·정상 복귀 → 버전 필드 없는 과거 영수증 복원 → V2 상자 두 배 지급·복귀 → C 보스 해금·리롤 → 저장 재개. 자산·런 진행·과거 영수증 보존과 프로필 검증 통과를 확인했다.
- 관리형 하네스는 네이티브 Unity JsonUtility 대신 공개 필드 직렬화 대체 구현을 사용한다. 네이티브 저장/게임 화면 실행을 검증한 결과는 아니다.
- 통합 diff의 `git diff --check`를 통과했다. 각 세션이 이미 수행한 무관한 테스트는 반복하지 않았다.

실제 화면에서 대시 종료 경계의 피격, 일반 적/보스 회전·공격 예고 방향, F2 버튼·교리 제목을 직접 조작하는 확인은 미실행이다. 특히 B의 공격 시작 지연은 기존 보스 PlayMode 테스트의 시간 가정에 영향을 줄 수 있다.

## 정리 범위와 다른 기기에서의 후속 조치

Puri 반영 후 각 완료 커밋의 조상 관계와 원격 tip을 확인하고, 이번 A/B/C 작업 및 통합용 원격 브랜치만 삭제한다. 이 기기에서는 C·통합 worktree와 해당 로컬 브랜치를 정리한다. `codex/first-altar-story-spec` 등 기존 브랜치는 대상이 아니다. 최종 푸시 SHA와 실제 정리 결과는 통합 세션의 최종 보고를 기준으로 한다.

다른 기기의 로컬 worktree와 브랜치는 이 기기에서 삭제하거나 완료 여부를 확인할 수 없다. A/B 세션에는 아래 취지의 완료 통지를 전달한다.

> 원격 Puri에 세 작업 통합이 완료됐다. fetch 후 본인의 완료 커밋이 origin/Puri에 포함됐는지 확인하고, 이번 작업의 깨끗한 worktree와 로컬 브랜치만 정리해 줘. 원격 작업 브랜치는 통합 담당이 정리한다. 기존 미커밋·미추적 파일과 다른 사용자 작업은 보존해 줘.

정리 전에 worktree 경로·브랜치 소유권·미커밋/미푸시 변경을 확인하고, 삭제할 폴더 밖의 원본 저장소에서 `git worktree remove`를 사용한다. `git clean`이나 포괄적 재귀 삭제로 기존 파일을 지우지 않는다. 미완료 작업을 발견하면 삭제하지 않고 보고한다.
