# 제작 레벨 배치 인수인계

기준 커밋 `3ac32d0e458a7f8f5662f1c236106a9951e91db6`에서 `codex/level-layouts` 작업으로 적용했다. 입력 자료는 `레벨디자인.xlsx`이며, 시트·셀 서식·문구를 표준 라이브러리로 확인했다. 병합 셀과 도형은 없었다.

## 다른 컴퓨터로 전달하기

작업 브랜치와 `/private/tmp/believe-clouds-level-layouts` 경로는 이 컴퓨터에만 있다. 다른 컴퓨터에서 같은 원격 브랜치를 확인할 수 있다고 가정하지 않도록, 이 브랜치의 커밋만 담은 Git bundle을 별도로 전달한다. bundle에는 이 브랜치의 커밋과 브랜치 참조만 포함하며, Puri·Leesc·다른 세션의 변경은 포함하지 않는다. 기준 커밋은 프로젝트의 세션 공통 기준인 `3ac32d0e458a7f8f5662f1c236106a9951e91db6`이다.

받는 컴퓨터에서 기준 커밋이 있는 저장소를 사용하고, 같은 이름의 로컬 브랜치가 없는지 확인한 뒤 다음처럼 가져온다.

```sh
git bundle verify /path/to/level-layouts-transfer.bundle
git fetch /path/to/level-layouts-transfer.bundle codex/level-layouts:refs/heads/codex/level-layouts
git switch codex/level-layouts
```

`git bundle verify`에서 기준 커밋이 없다고 나오면, 먼저 공통 저장소에서 그 기준 커밋을 가져온다. 같은 이름의 브랜치가 이미 있으면 덮어쓰지 말고 해당 브랜치의 커밋을 비교한 뒤 통합 담당이 선택한다. 원격 푸시나 다른 브랜치 병합 없이 bundle 파일만 별도로 전달한다.

## 좌표와 크기

제작 맵은 엑셀 가로·세로 한 칸을 타일맵 두 칸으로 대응시켰다. 엑셀 L열의 바닥 시작을 원점으로 두고, 개체는 표시 셀 중앙에 맞춘다.

`월드 X = 바닥 시작 X + (2 × (엑셀 열 − L열) + 1) × 타일 크기`

Tutorial과 일반 전투 맵의 타일 크기는 0.74 유닛이다. Lobby는 0.7435898, ShopTest는 0.7297846 유닛이며, 타일이나 캐릭터를 가로로 늘이지 않았다. 플레이어 프리팹의 충돌체와 이동 설정은 그대로 두었다. 현재 값은 폭 1, 높이 2 유닛, 이동 속도 7, 점프 힘 15.64, Rigidbody 중력 배율 4다. 기본 점프는 약 2.96 유닛, 약 4타일 높이다.

Lobby는 엑셀 P열 시작 위치가 기존 플레이어 위치 `x=-28`에 오도록 바닥 시작점을 정했다. 재단은 U열, 세 갈래 출구는 Z·AC·AF열 표식에 맞췄다. 2개 후보 경로는 양 끝 출구 위치를 재사용해 기존 2/3개 분기 선택 동작과 참조를 유지했다. 축소된 바닥 중심에 방 배경·경계·목적지 안내문을 맞췄고, 생성된 실내 베이도 새 폭에 맞게 다시 배치했다.

ShopTest는 바닥 시작점을 유지했다. 플레이어는 P열, 상점은 T:X 영역의 중앙 W열에 맞췄고 카메라·이동 제한을 바닥 폭에 맞췄다. 엑셀에는 AB열 출구 표식이 있지만 ShopTest 씬에는 대응하는 출구 오브젝트가 없었다. 기존 씬 흐름을 추측해 새 출구 기능을 만들지 않았다. 출구가 필요하면 통합 담당이 기존 상점 종료 흐름과 연결해야 한다.

활성 적 수는 엑셀 표식과 맞췄다. 기존 적의 이동·피해·보상 코드는 바꾸지 않았다. 시트에 없는 추가 적은 오브젝트와 구성 요소를 보존한 채 해당 씬에서만 비활성화했다.

기존 Platformer Set 지형·어두운 실내 미술·단방향 충돌체를 유지했다. 1~6번 맵의 기존 발판과 `Jump Link`를 남겼다. 엑셀에서 상자·출구·플랫폼으로 식별되는 기존 개체와 CombatLevel6 봉쇄선을 제거하거나 새로 만들지 않았다.

## 정적 확인과 남은 플레이 확인

다음 정적 확인을 수행했다.

- `python3 Tools/level_layout_rework.py --apply`를 재실행했을 때 씬 변경 없이 완료되는 것을 확인했다.
- `python3 Tools/level_layout_rework.py --check`로 9개 씬의 타일 폭, 활성 적 수·X 좌표, 분기 위치, 카메라/이동 경계, Tutorial 앵커를 확인했다.
- 기존 이동 속도·점프 힘·중력을 사용한 보수적 점프 연결 계산에서 7개 제작 맵의 모든 기존 발판과 연결 발판에 도달 가능한 경로가 있었다. 플레이어·적의 물리 설정과 씬 충돌 규칙은 변경하지 않았다.
- `git diff --check`를 통과했다.

Unity Editor/BatchMode, EditMode/PlayMode 테스트, 자동 플레이는 실행하지 않았다. 실제 플레이에서 점프 착지, 카메라 화면 가장자리, 축소된 Lobby/Shop 배경, 분기 선택 및 ShopTest 출구 필요 여부를 확인해야 한다.

## 통합 담당 인수인계

- 이 브랜치는 `codex/level-layouts`이며 보스·컷씬 브랜치와 별도로 기준 커밋에서 작업했다. 다른 브랜치를 가져오거나 병합하지 않았다. 다른 컴퓨터에는 인수인계 bundle을 전달해 위 절차로 가져온다.
- Tutorial 씬에는 컷씬 앵커와 `TutorialStoryBeliever` 식별만 추가했다. 컷씬 모듈과의 실제 연결은 세 브랜치 통합 후 담당 세션에서 수행한다.
- Lobby 라우팅/후보 배열의 기존 참조를 유지했다. ShopTest에는 엑셀의 출구 표식에 대응하는 기존 오브젝트가 없어 후속 흐름 결정이 필요하다.
- 보스 씬, 공용 프리팹·아틀라스·런타임 스크립트, ProjectSettings, Packages는 수정하지 않았다.
