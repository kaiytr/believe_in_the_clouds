# 첫 재단 스토리 — 1.1 구현 결과

작성일: 2026-11-11. 브랜치: `codex/first-altar-story-v1.1`. 1.0 기준 `main`의 `781af6d`는 변경하지 않았다. 배포 빌드는 이번 작업에서 생성하지 않았다.

## 적용한 흐름

신규 프로필은 튜토리얼 완료 후 첫 일반 전투 출구, 1.0 기존 프로필은 업데이트 후 다음 일반 전투 출구에서 전용 씬에 진입한다. 상점·보스·분기 리롤·해금 도구는 이벤트 진입을 소비하지 않는다. 프로필당 한 번이며 사망으로 새 런이 시작되어도 완료 기록을 유지한다.

신도 원고는 처음부터 첫 단독 사과까지 기존 CutsceneRunner로 한 번 재생한다. 이 구간은 이동·점프·대시·공격을 잠그며, 클릭 한 번으로 타이핑을 완성하고 그 다음 클릭으로 다음 대사를 진행한다. 마지막 클릭 해제 후 사과 자동 반복과 자유 이동으로 전환하며, 접근 범위에 있을 때 사망 컷씬을 시작한다.

반복 사과는 같은 말풍선에 총 20회까지만 누적하고 두 문장마다 줄바꿈한다. 문장 사이 대기나 구분 공백·줄바꿈의 타이핑 대기 없이 연속 출력하며, 완료 뒤에는 추가 문장 없이 최종 말풍선을 유지한다. 표시된 글자 수에 맞춰 말풍선 크기를 늘리며, 최대 크기에 도달하면 이전 줄을 위로 밀어 최신 문장을 표시한다. 완료 후에도 접근 사망 조건은 유지한다. 일반 컷씬 대사는 기존처럼 전체 문장을 기준으로 미리 크기를 확보한다.

신도 비주얼은 튜토리얼·전투 씬의 실제 합성 배율인 13/6(약 2.1667배)에 맞추고 발 위치·머리 앵커를 보정했다. 원본 스프라이트의 flipX를 켜 오른쪽 제단을 바라보며, 플레이어를 향해 회전하지 않는다. 말풍선 문자 치환과 신체 왜곡 글리치는 제거하고, 신도 프리팹과 씬 재작성 도구에 기본 Unlit 재질을 적용했다.

완전 암전 → 빗소리 상승 → 둔탁한 타격음 1회 → 타격음 뒤 실제 3초 암전 → 혈흔·시체가 있는 화면으로 즉시 복귀한다. 사망 저장 실패 시 혈흔 화면과 입력 잠금을 유지하며 저장만 재시도한다. 같은 실행에서 타격음과 암전을 다시 재생하지 않는다.

사망 저장 및 컷씬 종료 후 재단을 활성화한다. 기록 UI는 E로 열고 E/ESC/닫기 버튼으로 닫는다. 열람 저장 실패 시 창을 유지한다. 성공 후 방에 남으며, 키·마우스 해제를 거친 새 E 입력으로 출구에서 로비에 복귀한다. 재열람도 가능하다.

## 저장과 연결

- 저장 스키마 v5, `NarrativeProgressData`, `RunArea.StoryRoom=4`를 추가했다. 기존 enum 숫자와 `BranchRole=2` 제거 마이그레이션은 유지한다.
- 유효한 v1~v4 파일은 자산·런·사망 저널·TIP·영수증을 유지하고 LegacyEligible 자격을 추가한다. v5 필수 내러티브 영역이 빠진 파일은 새 이벤트로 초기화하지 않고 거부한다.
- 원본 Combat stage·상자 상태를 방 안에서 보관한다. 입장 때 클리어 +1, 실제 로비 복귀 때 visit +1·다음 후보 생성이다. 출구 영수증과 후보 seed는 기존 ID 계약을 유지한다.
- 기존 런 스냅샷 캐시를 제거하고 현재 거래 복사본에서 결정적으로 계산해 저장 실패 뒤 진행·HP가 덮어써지지 않도록 했다.
- 명세의 접근 트리거·사망 외부 단계·암전·오디오 책임은 `StoryRoomFlow`에 묶고, 기도·신도 표시·문서 UI·상호작용은 별도 컴포넌트로 분리했다. 연결 지점을 줄이면서 저장 단계와 입력 조건은 같은 계약을 따른다.
- 튜토리얼 연습 서비스가 아닌 정식 서비스에 완료를 저장하고, 정식 서비스를 복원한 뒤 로비를 로드한다. 타이틀은 PlayerPrefs 진입 키 대신 프로필의 tutorial 단계로 판단한다.
- F2 전체 초기화는 기존과 같이 새 프로필을 만든다. 튜토리얼 초기화 메뉴는 다음 Editor Play에서 격리된 메모리 프로필을 사용하고 실제 저장 파일은 유지한다.
- 컷씬·문서 UI·닫기 입력 해제 중에는 F2가 진행을 끊지 않는다. StoryRoom에서 보스 해금·분기 리롤은 비활성이다.

## 실제 수행한 검증

Unity `6000.3.5f2`에서 런타임·에디터·테스트 어셈블리 컴파일과 씬·프리팹·데이터·메타 생성이 완료됐다.

- 반복 사과 누적 변경 검증: PlayMode **10/10 통과** (`AmbientPrayerControllerPlayModeTests` 4개, `CutsceneRunnerPlayModeTests` 5개, `FirstAltarStoryPlayModeTests` 1개). 같은 말풍선 안의 문장 누적·두 문장마다 줄바꿈·타이핑 중 크기 유지/확대·모달 일시정지·중단/재시작·최대 크기에서 이전 줄 마스킹과 화면 안전 영역·일반 대사의 사전 크기 확보를 확인했다. 누적 텍스트가 말풍선 안에 들어가는 동안에는 일반 대사와 같은 가운데 정렬을 적용하고, 최대 높이를 넘을 때만 아래 정렬한다. 변경 전 아래 정렬로 넓어졌던 상단 여백을 재현한 뒤, 수정 후 1·2·5·10줄의 실제 글자 정점 위치로 일반 대사와 상단 여백이 같은 것을 확인했다. 정확히 20회까지 문장 사이 대기·문자 치환 없이 연속 타이핑하고 최종 말풍선을 유지하는 것도 확인했다. 실제 스토리 씬에서 기본 신도 재질, 사과 20회 완료 후 접근 사망, 클릭 도입부·저장 재시도·문서/출구 흐름이 통과했다. 별도 임시 프로젝트 복사본에서 실행했으며 Git 워크트리는 만들지 않았다.

- `FirstAltarStoryEditModeTests`: **8/8 통과**. 실제 Unity JsonUtility/JsonEconomyStore로 v1~v4 호환, v5 필수 단계 누락 거부, 저장 실패·진행 변경 후 재시도, 중복 거래, 클리어/방문 분리, 런 교체 후 재진입·완료 유지 확인.
- `FirstAltarStoryPlayModeTests`: **1/1 통과**. 사용자 피드백 수정 후 실제 씬에서 신도 13/6 배율·제단 방향, 도입부 조작 잠금, 클릭 타이핑 완료와 별도 클릭의 대사 진행, 자동 넘김 없음, 사과 반복 후 조작 복원을 추가 확인했다. 이후 접근 컷씬·실제 3초 암전·저장 재시도·재단/출구 순서·UI 닫기 저장 실패·새 E 입력 복귀도 통과했다. 도입부는 Runner의 동일 클릭 처리에 테스트 입력을 전달해 원고 전체를 진행했고, 사과 타이핑 속도·빗소리 상승만 테스트용 데이터에서 단축했다. 3초 암전은 단축하지 않았다.
- 전용 방의 생존·혈흔 구도를 오프스크린 렌더링해 확인했다. 최종 UI 디자인·청감·긴 원고 전체의 실제 속도는 수동 최종 연출 검수 범위로 남긴다.
- 문서 링크·원고 보존, Git 공백·메타·씬 참조를 확인했다. 전체 EditMode/PlayMode 회귀나 배포 빌드는 실행하지 않았다.

이 결과를 전체 프로젝트 테스트나 최종 1.1 배포 빌드 완료로 해석하지 않는다. 실제 배포 단계에서 `bundleVersion=1.1` 변경과 대상 플랫폼 빌드가 필요하다.

## 개발자 도구의 첫 재단 테스트

F2 → **첫 재단 스토리 테스트**를 누르면 기존 진행을 보관하고 도입부부터 재생한다. 완료한 프로필에서도 사용할 수 있다. 테스트 중 F2 → **첫 재단 스토리 · 처음부터**로 반복 재생하며, **테스트 종료 · 기존 진행 복귀**로 중간에 돌아올 수 있다. 스토리를 끝내고 방 출구를 사용해도 원래 진행으로 복귀한다.

- 원래 서비스와 씬을 살아 있는 상태로 보관한다. 원래 씬 루트는 비활성화하고, 테스트 씬만 Additive로 로드한다. 복귀 시 기존 플레이어·체력·위치·씬 객체·라우터를 다시 활성화한다.
- 기존 프로필의 복사본에서 테스트 전용 프로필/런 ID와 내러티브를 만든다. 재화·조각은 복사하지만 모든 테스트 거래는 MemoryEconomyStore에만 기록한다. 실제 최초 이벤트 기록·런·영수증과 저장 파일은 테스트로 갱신하지 않는다.
- 사망 결과·씬 전환·저장 실패·미정산 보상이 있으면 진입을 기다린다. 테스트 중에는 초기화·강제 사망·재화 지급 등 다른 수정 버튼을 비활성화한다.
- 도입부·암전 중에도 F2로 재시작/종료할 수 있도록 개발자 패널을 위에 표시한다. 패널이 위에 있을 때 아래 컷씬은 클릭을 소비하지 않는다.
- 실제 재단 방을 보관했다 복귀할 때는 저장된 단계로 연출을 다시 연결한다. 도입부 중이었다면 저장 규칙에 따라 원고 처음부터 재개하며, 이미 사망·열람한 단계는 유지한다.

`FirstAltarStoryPreviewPlayModeTests` **1/1 통과**: 실제 F2 버튼 연결, 완료 프로필의 도입부 진입, 도입부 중 재시작, 정상 출구의 원래 씬 복귀, 중간 종료, 원래 플레이어 객체·체력·위치·프로필 JSON 보존을 확인했다. 실제 임시 Json 저장 파일의 바이트도 테스트 전후 동일했다. 진행 중인 원래 StoryRoom의 인스턴스·사망 단계 복원도 확인했다. 열려 있던 사용자 Unity 세션은 건드리지 않고 독립 프로젝트 복사본에서 이 검증만 수행했다.
