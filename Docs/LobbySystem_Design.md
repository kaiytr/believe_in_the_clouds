## 1. 목적과 플레이 루프

로비는 다음에 진행할 스테이지를 선택하는 안전한 2D 공간이다. 플레이어는 스테이지를 진행하며 교리를 갖추고, 사망하면 현재 런의 진행이 초기화되며 일부 자산을 잃은 상태로 로비로 돌아온다.

사용자가 확정한 전체 목표 흐름:

**로비 → 분기 선택 → 스테이지 진입 → 스테이지의 역할 수행 → 분기 선택(수행 위치: 로비) → … → 보스 → 엔딩**

- 분기는 전투·상점·이벤트 등 역할이 다른 스테이지 중 하나를 고르는 것이다.
- 보스는 현재 런에서 일반 전투를 3회 클리어한 이후부터 후보로 등장할 수 있다.
- 일반 스테이지에서 로비로 돌아오는 조건은 **스테이지 완료 또는 사망**뿐이다.
- **중도 귀환·포기 귀환은 허용하지 않는다.**
- 게임 종료는 귀환이나 사망으로 취급하지 않는다. 이어 하면 진행 중인 영역의 저장 상태를 복원한다.
- 정식 보스 승리 이후의 목표는 엔딩이며, 엔딩 연출과 이후 자산 정책은 후속 범위다.

### 1.1 용어

| 용어 | 의미 |
| --- | --- |
| 런 | 시작부터 사망 또는 보스 승리까지 이어지는 한 차례의 진행 |
| 일반 전투 | 보스와 구분되는 전투 역할 스테이지. 보스 해금 횟수에 집계 |
| 후보 묶음 | 한 번의 로비 방문에서 제시되는 분기 2~3개 |
| 후보 | 역할·목적지·배치·공개 상태를 가진 분기 하나 |
| 역할 공개 | 특정 후보 하나에 5코인을 지불하고 스테이지 역할만 알아내는 행위 |
| 정상 복귀 | 스테이지 완료 후 출구에서 E를 눌러 로비로 돌아오는 행위 |
| 이어 하기 | 같은 런·같은 로비 또는 진행 중 스테이지를 저장 상태에서 계속하는 행위 |

## 2. 로비 공간·시설·조작

### 2.1 공간과 카메라

- 플레이어가 직접 이동하는 **가로로 긴 2D 로비**로 구성한다.
- **카메라는 플레이어를 따라간다.** 로비 전체가 한 화면에 보이는 고정 카메라 구성으로 만들지 않는다.
- 적·위험요소가 없는 안전 공간이며, 이동 경계와 바닥은 낙사 등 의도하지 않은 피해가 생기지 않게 구성한다.
- 기존 **이동·점프·대시·공격 조작을 모두 허용**한다.
- 로비에 들어왔다는 이유로 코인·조각·장착을 신규 프로필처럼 초기화하지 않는다.

### 2.2 시설

- 분기 스테이지 역할은 **일반 전투·상점·이벤트·해금 후 보스**다.
- **재단은 분기 스테이지가 아니다.** 추후 재단 구현이 완료되면 로비 내부 시설로 배치한다.
- 이번 로비 개발을 위해 재단 전체를 먼저 구현하지 않는다.
- 그 외 회복 시설·NPC 등을 이번 확정 기능에 추가하지 않는다. 필요하면 후속 기획에서 결정한다.

### 2.3 입력

| 입력·행동 | 동작 |
| --- | --- |
| 후보 근처에서 E | 해당 분기로 즉시 출발. 확인창 없음 |
| 미공개 후보 근처에서 F | 5코인을 지불하고 해당 후보의 역할을 즉시 공개. 확인창 없음 |
| 공개된 후보 근처에서 F | 추가 결제 없음. 공개 상태 유지 |
| 후보에 겹치거나 지나감 | 이동만 수행. 자동 출발·자동 결제 없음 |
| 완료된 임시 스테이지 출구에서 E | 정상 복귀 |
| 완료 전 복귀 시도 | 로비 복귀 불가 |

기존 일반 시설의 E 상호작용은 유지한다. F는 분기 역할 공개용 추가 입력이며 모든 시설의 공통 상호작용 키를 바꾸는 것이 아니다.

## 3. 분기 오브젝트와 정보 표시

### 3.1 외형과 이동

- 후보마다 **큰 사각형 오브젝트**를 배치한다. 사용자가 설명한 스컬 느낌을 방향으로 삼되 현재는 사각형으로 표현한다.
- 플레이어와 물리 충돌하지 않으며 겹쳐 지나갈 수 있다.
- 겹치면 플레이어가 사각형 앞쪽에 보인다. 사각형이 플레이어를 가리지 않는다.
- 물리 충돌이 없어도 접근·거리 판정과 E/F 입력의 대상이 될 수 있어야 한다.

### 3.2 기본 정보와 유료 공개

| 항목 | 확정 규칙 |
| --- | --- |
| 기본 상태 | 모든 후보의 역할 비공개 |
| 공개 대상 | 플레이어가 선택한 후보 하나 |
| 비용 | **5코인 고정** |
| 공개 내용 | **스테이지 역할만** 공개 |
| 다른 정보 | 다른 후보의 역할, 등장 적, 난이도, 보상 등은 함께 공개하지 않음 |
| 공개 후 외형 | 해당 후보를 공개 상태로 전환하고 역할별 색상으로 변경 |
| 재확인 | 공개 상태를 유지하며 추가 비용 없음 |
| 미공개 출발 | 가능. 정보 공개는 입장 필수 조건이 아님 |
| 보스 | 기본 비공개·5코인 공개·미공개 출발을 동일하게 적용 |

예: 후보 3개 중 두 번째 후보를 공개하면 두 번째 후보만 역할에 맞는 색상으로 바뀐다. 첫 번째·세 번째 후보는 미공개 상태를 유지한다.

신규 시작 자산은 기존 규칙대로 0코인·0조각·장착 없음이다. 공개하지 않고도 출발할 수 있으므로 0코인에서도 진행 가능하다. 첫 로비에도 무료 공개나 전투 전용 후보 등의 예외를 추가하지 않는다.

### 3.3 조작·결제 구현 계약

아래는 확정 조작과 기존 경제 거래 규칙을 만족시키기 위한 설계 계약이다.

- 비용은 누르기 전 안내한다. 안내 문구와 별개로 E/F 실행에 확인창을 추가하지 않는다.
- 인식 범위 내의 후보 하나를 대상으로 강조·안내하고, E와 F가 같은 후보를 대상으로 동작하게 한다.
- 잔액이 5코인보다 적으면 차감과 공개를 모두 적용하지 않는다. 미공개 출발은 계속 가능하다.
- 5코인 차감과 공개 상태 변경은 같은 저장 작업으로 확정한다. 저장 실패에서는 둘 다 적용하지 않는다.
- 키 유지·연타·중복 요청으로 같은 후보에 중복 결제하지 않는다.
- 공개는 후보의 역할을 보여주는 행위다. 실제 역할을 새로 추첨하지 않는다.
- 이미 공개됨·코인 부족·저장 실패·전환 중 상태를 구분해 안내한다.
- 씬 전환이나 모달 UI가 진행 중이면 분기 입력을 잠그고, 한 번의 E 입력으로 여러 스테이지에 연속 진입하지 않게 한다.

## 4. 후보 생성 규칙

### 4.1 생성 시점

- 새 런의 최초 로비, 정상 스테이지 완료 후 복귀, 사망 후 새 런의 로비에서 새 후보 묶음을 생성한다.
- 첫 로비도 일반 생성 규칙을 그대로 적용한다.
- 로비에서 종료 후 이어 하기는 새 방문이 아니다. 기존 후보·배치·공개 상태를 복원한다.
- 출발하거나 공개했다는 이유로 현재 후보의 역할을 다시 추첨하지 않는다.

### 4.2 생성 순서

1. 후보 수를 **2개 50% / 3개 50%**로 결정한다.
2. **일반 전투 후보 1개를 먼저 포함**한다. 보스가 등장해도 이 보장은 유지한다.
3. 나머지 각 칸은 현재 추첨 가능한 역할에서 **동일 가중치**로 선택한다.
4. 보스 해금 전 추첨 대상은 **전투·상점·이벤트**다. 해금 후에는 **보스**를 추가한다.
5. 일반 전투는 뽑힌 뒤에도 추첨 대상에 남긴다. 상점·이벤트·보스는 한 번 뽑히면 해당 묶음의 남은 칸 추첨 대상에서 제외한다.
6. 완성된 후보의 좌우 위치를 섞는다. 보장된 전투가 항상 같은 자리에 나오지 않게 한다.
7. 후보별 식별자·역할·배치·기본 미공개 상태를 확정해 저장한다.

같은 가중치는 **보장된 일반 전투를 제외한 각 칸에서, 그때 허용되는 역할들의 가중치가 같다**는 뜻이다. 일반 전투 보장·중복 제한 때문에 최종 후보 전체의 역할별 등장 비율이 정확히 같아지는 것은 아니다.

### 4.3 중복과 조합

| 역할 | 묶음 내 제한 |
| --- | --- |
| 일반 전투 | 최소 1개, 중복 허용 |
| 상점 | 최대 1개 |
| 이벤트 | 최대 1개 |
| 보스 | 해금 후 최대 1개 |
| 재단 | 후보에 포함하지 않음 |

| 조건 | 가능한 조합 |
| --- | --- |
| 해금 전·2개 | 전투+전투, 전투+상점, 전투+이벤트 |
| 해금 전·3개 | 전투+전투+전투, 전투+전투+상점, 전투+전투+이벤트, 전투+상점+이벤트 |
| 보스 포함·2개 | 전투+보스 |
| 보스 포함·3개 | 전투+보스+전투, 전투+보스+상점, 전투+보스+이벤트 |

목록 순서는 실제 배치 순서가 아니다. 보스 해금 후에도 보스가 포함되지 않은 일반 후보 묶음이 나올 수 있다.

## 5. 런 진행과 보스 해금

### 5.1 집계 기준

- **현재 런의 일반 전투 스테이지 클리어만 1회씩 집계**한다.
- 상점·이벤트 완료, 단순 스테이지 진입, 정보 공개는 집계하지 않는다.
- 완료·복귀를 중복 요청하거나 완료 상태에서 재실행해도 같은 스테이지를 여러 번 집계하지 않는다.
- 사망하면 런 진행과 전투 클리어 수를 초기화한다.
- 로비 또는 임시 스테이지에서 종료 후 이어 하면 같은 런의 진행을 유지한다.

### 5.2 해금 규칙

| 전투 클리어 수 | 보스 처리 |
| --- | --- |
| 0 | 선택 불가, 일반 후보만 생성 |
| 1~2 | 선택 불가, 일반 후보만 생성 |
| 3 이상 | 나머지 후보 칸의 추첨 대상에 보스를 같은 가중치로 추가 |

- 세 번째 전투 클리어를 반영하고 로비로 복귀할 때 생성하는 후보부터 해금 규칙을 적용한다.
- 보스는 기존 후보 수 2~3개 안에 포함한다. 별도 입구나 추가 네 번째 후보를 만들지 않는다.
- **보스 전용 등장 확률이나 보장 슬롯은 두지 않는다.** 다른 역할과 함께 추첨하며 묶음당 최대 1개다.
- 보스가 나오더라도 일반 전투 최소 1개 보장은 유지한다.
- 보스가 나타나도 다른 일반 후보를 선택할 수 있다. 보스 진입을 강제하지 않는다.
- 보스도 기본 비공개이며 F로 5코인을 지불하면 역할을 공개한다. 공개 없이 E로 진입할 수도 있다.
- 사망 후 새 런은 클리어 수 0으로 시작하므로 보스가 다시 잠긴다.

## 6. 출발·완료·사망·복귀

### 6.1 출발

1. 플레이어가 후보 근처로 이동한다.
2. 필요하면 F로 해당 역할을 공개한다. 공개하지 않고 진행해도 된다.
3. E를 누르면 해당 후보로 즉시 출발한다.
4. 선택한 분기와 진행 중 스테이지를 저장하고 씬을 전환한다.
5. 출발 후에는 완료 또는 사망 전까지 로비로 중도 귀환할 수 없다.

출발 직후 종료해도 후보를 다시 고르는 로비로 보내지 않는다. 이어 하면 선택한 진행 중 스테이지를 복원한다.

### 6.2 정상 복귀

- 첫 구현의 임시 스테이지는 테스트 조작으로 역할 완료 상태를 만든다.
- 완료 전에는 로비 복귀 출구를 사용할 수 없다.
- 완료 후 출구에서 **E를 눌러 로비로 복귀**한다.
- 일반 전투 완료는 이 완료·복귀 거래에서 한 번만 클리어 수에 반영한다. 상점·이벤트는 클리어 수를 올리지 않는다.
- **남은 HP를 그대로 유지**한다. 로비 복귀를 이유로 자동 회복하지 않는다.
- 코인·조각은 정상 복귀를 이유로 차감하거나 초기화하지 않는다.
- 로비에 새 후보 묶음을 생성하고, 새 후보는 기본 미공개로 제시한다.
- 실제 장착의 정상 씬 전환 유지·복원은 후속 재단/장착 연동에서 같은 계약으로 연결한다.

### 6.3 사망 복귀

기존 재화 규칙에 따라 다음 순서를 유지한다.

1. 사망을 확정하고 신규 처치 보상 접수를 차단한다.
2. 기존 사망 교리 효과를 한 번 처리한다.
3. 교리를 전부 미장착으로 돌리고 효과·구독·버프·슬롯 연결을 정리한다.
4. 비행 중 대기 보상을 포함한 코인 총액과 전체 원본 보유 조각 목록에서 손실을 계산한다.
5. 손실 결과·미장착 상태·기존 런 종료·새 런 시작 상태를 일관되게 저장한다.
6. 로비로 돌아와 **최대 HP로 부활**한다.
7. 전투 클리어 수 0에서 새 후보 묶음을 생성한다. 보스는 다시 잠긴다.

| 자산 | 손실 |
| --- | --- |
| 코인 | `floor((보유 + 비행 중 대기) × 30 / 100)` |
| 조각 | `floor(전체 해제 후 원본 보유 조각 총수 × 30 / 100)`개를 개체별 동일 확률로 비복원 추출 |
| 장착 | 전부 해제. 이전 조합을 자동 재장착하지 않음 |

‘일부 교리를 잃는다’는 설명은 위 조각 손실 정책을 따른다. 완성 교리 수를 따로 세어 추가 소실시키거나 자산을 전부 0으로 초기화하지 않는다.

저장 실패 중에는 로비 복귀를 완료하지 않는다. 같은 사망을 재시도해도 최초 손실 계획을 유지하고 손실·새 런 생성이 중복 적용되지 않게 한다.

### 6.4 중도 귀환과 종료의 구분

- **중도 귀환·포기 귀환 기능을 제공하지 않는다.** 완료 또는 사망으로만 로비에 복귀한다.
- ESC나 메뉴 닫기, 일시정지 등은 로비 귀환 동작이 아니다.
- 게임을 종료했다고 사망 손실을 적용하거나 스테이지 완료로 처리하지 않는다.
- 종료 후 이어 하면 같은 임시 스테이지·남은 HP·완료 여부를 복원한다.

### 6.5 상황별 결과

| 상황 | 런 진행 | 로비 후보 | HP | 경제·장착 |
| --- | --- | --- | --- | --- |
| 신규 프로필 최초 시작 | 전투 클리어 0 | 일반 규칙으로 새 후보 | 기존 플레이어 설정의 최대 HP | 0코인·0조각·장착 없음 |
| 일반 전투 완료 후 복귀 | 클리어 수 +1, 한 번만 | 새 후보 | 남은 HP 유지 | 복귀 자체에 따른 추가 손실 없음 |
| 상점·이벤트 완료 후 복귀 | 전투 클리어 수 유지 | 새 후보 | 남은 HP 유지 | 복귀 자체에 따른 추가 손실 없음 |
| 사망 후 복귀 | 새 런, 전투 클리어 0 | 새 후보, 보스 재잠금 | 최대 HP | 30% 버림 손실·전체 해제 |
| 로비에서 종료 후 이어 하기 | 저장된 런 유지 | 기존 후보·배치·공개 상태 복원 | 저장된 현재 HP 유지 | 같은 시점의 경제 상태 복원·재공개 비용 없음 |
| 임시 스테이지에서 종료 후 이어 하기 | 선택한 스테이지·완료 여부 유지 | 재추첨·분기 재선택 없음 | 저장된 남은 HP 유지 | 같은 시점의 경제 상태 복원·완료/사망 중복 없음 |

정식 보스 승리는 전체 목표 흐름의 엔딩으로 연결한다. 첫 구현에서는 임시 보스 목적지의 선택·진입과 완료 상태를 검증하고, 완료 표시를 정식 엔딩 구현으로 보고하지 않는다. 엔딩 이후 로비 복귀·재시작·자산 계승 정책은 후속 결정이다.

## 7. 저장·복원과 일관성 계약

### 7.1 필수 저장 상태

| 영역 | 필요한 상태 |
| --- | --- |
| 런 | 런 식별자, 현재 진행 영역, 현재 런의 전투 클리어 수, 진행/종료 상태 |
| 생명·사망 | 생명/사망 식별자, 사망 처리 단계, 확정 손실 결과와 적용 여부 |
| 로비 후보 | 묶음 식별자, 후보별 식별자·실제 역할·목적지 연결·배치 순서·공개 여부 |
| 임시 스테이지 | 선택한 후보·스테이지 식별자·역할·완료 여부·완료/복귀 처리 여부 |
| 플레이어 | 현재 HP와 복귀/이어 하기의 적용 상태 |
| 경제 | 코인·조각·대기 보상·거래 ID·사망 저널 등 기존 경제 프로필 상태 |

색상은 역할과 공개 상태에서 표현한다. 역할 정보가 저장되어 있어도 미공개 후보의 플레이 화면에는 노출하지 않는다.

### 7.2 함께 확정할 변경

| 작업 | 같은 저장 시점으로 확정할 내용 |
| --- | --- |
| 역할 공개 | 코인 5 차감 + 해당 후보 공개 |
| 분기 출발 | 선택한 후보 + 진행 중 스테이지 + HP·경제 상태 |
| 정상 복귀 | 완료 1회 반영 + HP 유지 + 다음 로비·새 후보 + 경제 상태 |
| 사망 복귀 | 기존 사망 손실 + 전체 해제 + 새 런·클리어 수 0 + 최대 HP 부활 + 새 후보 |
| 이어 하기 | 저장된 영역·런·후보 또는 스테이지·HP·경제 상태를 같은 시점으로 복원 |

- 저장 성공 후 공개 상태·잔액·다음 씬을 게시한다. 저장 실패 시 부분 성공을 노출하지 않는다.
- 재시도에서 공개를 중복 결제하거나 완료 수를 중복 증가시키지 않는다.
- 새 후보를 포함한 전환 계획도 재시도 중 유지해 저장 실패를 이용한 반복 추첨이 되지 않게 한다.
- 비행 중 코인은 기존 예약 권리를 유지하고, 씬 전환·사망·종료에서 누락이나 중복 정산이 없게 기존 경제 계약과 연결한다.
- 손상본·미지원 저장 버전은 보존하고 거래를 잠근다. 오류를 신규 프로필 0자산으로 자동 덮어쓰지 않는다.
- 테스트 저장은 실제 사용자 프로필과 분리한다.

이 표는 게임 규칙을 만족시키기 위한 저장 책임 계약이다. 구체 클래스·파일 구조·저장 스키마 변경은 구현 명세에서 정하고, 현재 경제 저장이 이미 런·스테이지를 함께 저장하는 것으로 간주하지 않는다.

## 8. 첫 구현 범위와 임시 스테이지

### 8.1 포함

- 긴 안전한 2D 로비와 추적 카메라, 기존 플레이어 조작.
- 통과 가능한 큰 사각형 분기, E 즉시 출발·F 즉시 공개.
- 후보 생성·동일 가중치·중복 제한·위치 섞기·보스 해금 규칙.
- 5코인 공개와 공개 상태 저장, 로비 및 임시 스테이지 이어 하기.
- 임시 스테이지의 역할 표시, 테스트용 완료·피해·사망 조작.
- 완료 후 출구 E 복귀, 생존 HP 유지, 사망 손실·런 초기화·최대 HP 부활.
- 자동 테스트와 사용자가 직접 검증할 테스트 씬·가이드.

### 8.2 임시 스테이지 흐름

1. 선택한 역할을 표시한다. 역할별 실제 콘텐츠가 완성된 것으로 보이게 하지 않는다.
2. 테스트용 완료·피해·사망 조작으로 상태를 만든다.
3. 완료 전 출구는 사용할 수 없다. 완료 후 출구에서 E로 로비에 복귀한다.
4. 일반 전투 완료는 클리어 수 증가, 상점·이벤트 완료는 증가 없음으로 검증한다.
5. 종료/재실행 뒤 선택한 역할·HP·완료 여부를 복원한다.
6. 보스는 해금 전후 후보 생성·공개·선택·진입과 테스트 완료 상태까지 확인한다.

유료 공개 테스트에 필요한 코인은 격리된 테스트 준비 도구나 자동 테스트에서 지급한다. 실제 신규 프로필 0코인 규칙을 변경하지 않는다. 테스트용 조작은 정식 스테이지의 플레이 규칙과 구분한다.

### 8.3 후속 연결

- 실제 전투·상점·이벤트 스테이지의 콘텐츠와 역할 완료 조건.
- 실제 재단의 조합·장착·해제 UI와 로비 시설 배치.
- 실제 장착 조각 연결과 정상 씬 이동 시 효과·장착 상태 유지/복원.
- 실제 보스 전투, 정식 엔딩, 엔딩 이후 자산 초기화/계승 정책.
- 실제 전투 스테이지의 위치·적 생사·HP·보스 페이즈 등 전체 이어 하기.
- 정식 아트·사운드·연출 조정.

기존 StageTest는 전투 통합 검증 씬이다. 이번 임시 스테이지 왕복 검증이 실제 콘텐츠 전체와 메인 루프·엔딩 완성을 뜻하지 않는다.

## 9. 화면·연출 초기안

아래는 최종 아트 확정이 아니라 구현 후 테스트로 조정할 초기안이다. 후보 역할·비용·생성·복귀·저장 규칙은 조정 항목에 포함하지 않는다.

| 항목 | 초기안 |
| --- | --- |
| 구역 | 시작/귀환 위치, 향후 재단 공간, 분기들이 늘어선 구역을 가로로 구분 |
| 크기·간격 | 플레이어보다 큰 사각형, 인접 후보의 대상이 혼동되지 않는 간격 |
| 카메라 | 로비 범위 안에서 추적. 구체 추적 속도·축·경계 수치는 테스트 조정 |
| 미공개 후보 | 같은 중립 회색 사각형과 비공개 표시 |
| 공개 후 색상 | 전투 빨강 / 상점 금색 / 이벤트 파랑 / 보스 보라 |
| 보조 표시 | 공개 후 역할명 표시를 기본 제안으로 두고 가독성을 확인 |
| 접근 안내 | 대상 하나 강조, 해당 분기 위에 E 출발 / F 역할 공개 5코인 표시. 출구 안내도 출구 위에 부착하고 카메라 이동을 추적 |
| 상태 안내 | 공개됨·코인 부족·저장 실패·전환 중 표시 |
| HUD | 기존 HP·코인 HUD 활용. 디버그 역할 정보가 미공개 후보에 노출되지 않도록 구분 |

큰 사각형·플레이어 통과·캐릭터가 앞에 보임·긴 로비의 추적 카메라는 확정 사항이며 연출 초기안과 별개로 유지한다.

## 10. 검증 기준

아래는 자동·수동 검증 기준이다. 실행 결과와 수동 확인 여부는 구현 결과서에서 구분한다.

| 범위 | 확인할 결과 |
| --- | --- |
| 최초 로비 | 0코인·0조각·장착 없음, 일반 후보 규칙 적용, 보스 없음 |
| 공간 | 긴 로비를 이동하며 카메라 추적, 기존 이동·점프·대시·공격 가능, 안전 경계 |
| 통과 | 사각형에 막히지 않고 캐릭터가 앞을 지나감. 겹침만으로 출발·결제 없음 |
| 후보 수 | 2/3 각각 50% 추첨, 새 생성 결과가 저장되고 이어 하기에서 재추첨 없음 |
| 구성 | 일반 전투 최소 1개, 전투만 중복 허용, 역할별 허용 풀의 동일 가중치, 위치 섞기 |
| 보스 잠금 | 전투 클리어 0~2회에는 후보에 보스 없음 |
| 보스 해금 | 전투 3회 이후 같은 가중치로 후보에 포함 가능, 최대 1개·일반 전투 보장·총수 2~3 유지 |
| 집계 | 상점·이벤트·단순 진입은 횟수 증가 없음. 같은 전투 완료/복귀의 중복 증가 없음 |
| 비공개 | 공개 전 역할·난이도·보상 등이 외형·문구로 미리 노출되지 않음 |
| 유료 공개 | F로 5코인 차감 후 대상 하나의 역할만 공개·색상 변경. 보스도 동일 |
| 입력 | E/F 확인창 없음, 선택 대상 일치, 키 유지·연타·전환 중 입력의 중복 실행 없음 |
| 잔액 경계 | 5코인은 공개 후 0, 5 미만은 차감·공개 없음. 미공개 출발은 가능 |
| 재공개 | 이미 공개한 후보에 F 입력/재실행을 해도 추가 차감 없음 |
| 저장 실패 | 공개 비용·공개 상태·씬 이동·새 후보가 부분 적용되지 않고 재시도 결과가 일관됨 |
| 정상 복귀 | 완료 후에만 출구 E 사용 가능, 남은 HP 유지·새 후보 생성 |
| 중도 귀환 | 완료 전 메뉴·출구·임의 입력으로 로비에 복귀하지 않음 |
| 사망 복귀 | 기존 30% 손실·전체 해제 한 번, 새 런·클리어 수 0·새 후보·최대 HP·보스 재잠금 |
| 로비 복원 | 종료 후 같은 후보·배치·공개 상태·HP·진행·경제 상태 복원 |

## 11. 현재 정리 상태

- 첫 구현 범위의 게임 규칙은 사용자 답변으로 정리했다.
- 중도 귀환은 금지, 완료 또는 사망으로만 로비 복귀한다.
- 배치·크기·색상 등은 조정 가능한 초기안을 따로 두었다.
- 실제 역할별 콘텐츠·재단·정식 엔딩·전투 전체 이어 하기는 후속 범위다.
- 사용자 구현 시작 지시에 따라 첫 구현 범위의 코드·씬·자동 테스트를 추가했다.
