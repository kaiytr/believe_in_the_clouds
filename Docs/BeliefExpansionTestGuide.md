- 작성일: 2026-10-25
- 프로젝트: `believe_in_the_clouds`
- Unity 버전: **6000.3.5f2**
- 기준 씬: [BeliefTest.unity](../Assets/Scenes/BeliefTest.unity)
- 관련 문서: [확장 명세](../BeliefSystem_ExpansionSpec.md), [구현·검증 기록](../BeliefSystem_ExpansionImplementationStatus.md)

## 1. 현재 작업 상태

일반 적 믿음 9종과 더미 적중 도구를 구현했다. **플레이어 공격은 구현하지 않았다.** 적중이 필요한 조건은 더미 데이터로 확인한다. **9종을 하나씩 직접 플레이하며 확인하는 작업은 미완료**이며, 사용자가 이 문서를 기준으로 진행한다.

이전에 저장된 자동 검사 결과는 EditMode 42/42, PlayMode 37/37 통과다. 결과 파일은 각각 `Logs/BeliefDummyEditMode.xml`, `Logs/BeliefDummyPlayMode.xml`이다. 이후 추가한 검증 창이나 9종 직접 플레이 검증이 완료됐다는 의미는 아니다. `Logs`는 Git에서 제외되므로 다른 컴퓨터에 결과 파일이 없을 수 있다.

`Tools > Belief > 9종 직접 검증` 메뉴를 만드는 [BeliefManualVerificationWindow.cs](../Assets/Editor/BeliefManualVerificationWindow.cs)도 추가된 상태다. **이 창은 동작 확인을 끝내지 못했다.** 아래 절차는 해당 창을 사용하지 않고, 기존 테스트 씬의 Inspector와 더미 패널을 사용하는 방법이다.

## 3. 테스트 준비

1. Play를 종료하고 `Assets/Scenes/BeliefTest.unity`를 연다. 열려 있는 미완성 검증 창은 닫는다.
2. Hierarchy에서 확인할 적 하나만 활성화하고 나머지 적 두 개는 비활성화한다.
   - 개: `Dog`
   - 신자: `Believer`
   - 간부: `Executive`
3. `TestPlayer`, `Ground`, `Main Camera`, `BeliefDummyData`는 활성 상태로 유지한다.
4. 확인할 적의 **BeliefController > Belief Type Candidates**를 펼친다.
5. 목록의 **Size를 1**로 바꾸고, Element 0을 5장 표의 종류로 지정한다. Inspector에는 enum 이름에 공백이 들어가 표시될 수 있다.
6. Play를 시작하고 왼쪽 위 패널에서 확인할 적을 선택한다.
7. 말풍선이 지정한 믿음과 일치하고, 패널의 초기 믿음이 100인지 확인한다.

**Belief Type 필드만 바꾸면 후보 목록이 우선하므로 고정되지 않는다.** 반드시 `Belief Type Candidates`를 해당 종류 하나로 지정한다. 플레이 중 후보를 바꿔도 이미 배정된 믿음은 바뀌지 않는다.

믿음을 바꿀 때마다 **Play 종료 → 후보 변경 → 다시 Play** 순서로 진행한다. 각 표의 기대 값은 초기 믿음 100에서 시작한 기준이다.

기본 조작은 A/D 또는 좌우 방향키로 이동, Space로 점프다. 이동 입력 전 Game 뷰에 포커스를 둔다. F2로 더미 패널을 숨기거나 표시할 수 있다. Game 뷰를 충분히 크게 두면 패널과 말풍선을 함께 보기 쉽다.

## 4. 더미 입력 사용법

`BeliefDummyData`의 `BeliefDummyHitTool` 기본 설정:

| 항목 | 값 |
| --- | --- |
| Hit Data > Base Damage | 1 |
| Hit Data > Kind | Direct |
| Hit Data > Hit Index | 0 |
| Burst Interval | 0.25초 |
| 일반 적 기본 HP | 30 |

피해 1을 사용하면 적중 횟수를 확인하기 전에 적이 죽는 상황을 줄일 수 있다. 기본 설정을 유지한 상태에서 먼저 검사한다.

| 패널 버튼 | 동작 |
| --- | --- |
| Dog / Believer / Executive | 더미 적중을 보낼 대상을 선택한다. 대상 선택은 적의 활성 상태나 믿음 종류를 바꾸지 않는다. |
| 적중 데이터 1회 | 새 타격 ID로 더미 적중을 한 번 보낸다. |
| 연속 데이터 5회 | 0.25초 간격으로 최대 5번 보낸다. 붕괴·사망·대상 변경·도구 비활성화 시 중지한다. |
| 직전 타격 재전송 (중복 검사) | 직전과 같은 대상·타격 ID·순번으로 다시 전송한다. 정상이라면 중복 거부된다. |

더미 입력은 거리·무기·공격 애니메이션을 검사하지 않는다. 대신 실제 HP 감소와 믿음 판정 경로를 통과한다. **후방 여부는 실제 플레이어 위치**, 회피는 **실제 적 공격 결과**, 시전 중 적중은 **실제 마법진 준비 상태**를 사용한다.

단발 적중 버튼은 매번 새 공격 ID를 만들므로 기본 Hit Index가 계속 0이어도 독립된 타격이다. 지속 피해나 소환물 Kind는 HP 피해를 줄 수 있지만 적중형 믿음 공략에서는 제외된다.

| EXE-02 | Executive / `ExecutiveRearPosition` | 간부가 공격 준비로 방향을 고정했을 때 뒤로 이동해 연속 2초 체류한다. 네 번 성공시킨다. | 성공마다 100 → 75 → 50 → 25 → 0. 중간에 벗어나면 미완료 체류 시간 초기화. |

### 조건별 주의점

- **DOG-01:** 2초는 경고에서 벗어난 순간이 아니라 공격의 최종 회피 결과가 확정된 시각부터 계산한다. 처음부터 경고 범위 밖에 있었거나 돌진이 벽에 막힌 경우는 유효 회피가 아니다.
- **DOG-02 / BEL-02:** 해당 공격이 정상 종료됐고 실제 HP 피해가 없었는지를 확인한다. 다른 적·환경의 피해와 섞어 비교하지 않는다. 돌은 발사 시점에 감소하지 않는 것이 정상이다.
- **DOG-03 / EXE-02:** 몸체 사이 가로 간격 4 이내, 몸체 중심 높이 차이 1.5 이내여야 한다. 단순히 화면의 왼쪽이나 오른쪽이 아니라 적의 시선 반대편이어야 한다.
- **BEL-01:** 인접한 적중 사이가 각각 2초 이내면 연속으로 센다. 간격이 2초를 넘으면 다음 타격은 새 첫 타격이 되어 감소하지 않는다. 이미 줄어든 믿음 값이 100으로 복구되는 것은 아니다.
- **BEL-03:** 현재 후퇴 범위는 적과 플레이어의 Transform 기준 가로 거리 4.5다. 가까이 있다는 조건과 실제 Retreat 상태가 함께 필요하다. 두 번째 성공은 후퇴가 끝난 뒤 새 후퇴 구간에서 확인한다.
- **EXE-01:** 경고 중 실제로 위협받았다가 효과 시점에 범위를 벗어나야 한다. 처음부터 멀리 떨어져 있는 것만으로 성공하지 않는다.
- **EXE-02:** 해당 믿음의 마법진 준비 시간은 최소 3초다. 매번 후방 연속 2초를 채우면 25 감소한다. 네 번의 성공 사이에는 후방을 벗어나도 이미 감소한 값은 유지된다.
- **EXE-03:** 준비 중 두 적중이 들어가야 한다. 더미 5회 입력이 붕괴 후 2회에서 중지돼도 정상이다.

## 6. 공통 판정·UI 확인

- 단발 적중 직후 **직전 타격 재전송**을 누르면 중복 거부 메시지가 나오고 HP·믿음 모두 유지돼야 한다.
- 믿음 0에서 취약 상태로 진입하고, 5초 뒤 **같은 믿음으로 100 회복**해야 한다.
- 기본 피해 1의 실제 HP 감소량은 믿음 유지 중 0.6, 취약 중 2다. 붕괴를 일으킨 타격은 적중 직전의 유지 배율 0.6을 사용한다.
- 적이 사망하면 사망 처리가 우선하므로 믿음 붕괴 테스트와 구분한다.
- 패널의 수치, 머리 위 믿음 게이지, 말풍선 문구가 서로 일치하는지 확인한다.
- 긴 한국어 문구의 잘림·줄바꿈과 HP 게이지 표시를 확인한다.
- 연속 더미 입력 중 대상을 바꾸면 이전 대상에 대한 예약 입력이 중지돼야 한다.
- 적이나 플레이어가 비활성·사망 상태면 더미 입력이 거부될 수 있다. 패널 아래 상태 문구를 확인한다.

## 7. 테스트 종료와 다른 컴퓨터에서 이어 하기

테스트 후에는 Play를 종료한다. 테스트용으로 바꾼 후보·활성 상태를 씬에 저장했다면, 일반 동작으로 돌아갈 때 세 적을 모두 활성화하고 후보를 다음처럼 복원한다.

| 적 | 기본 후보 3개 |
| --- | --- |
| Dog | `DogCounterattack`, `DogUnerringAttack`, `DogRearAttack` |

다른 컴퓨터에서는 Unity 6000.3.5f2로 프로젝트를 열고 이 문서의 3장부터 진행한다. 문서 링크는 저장소 기준 상대 경로이므로 컴퓨터의 사용자명이나 저장 위치가 달라도 사용할 수 있다.

**이 가이드와 구현 변경 파일을 함께 전달해야 한다.** Git으로 이동한다면 수정된 코드·씬·프로필과 새 파일의 `.meta`, 관련 문서를 함께 커밋·푸시한 뒤 다른 컴퓨터에서 받아야 한다. 로컬에 문서를 저장하는 것만으로 다른 컴퓨터에 반영되지는 않는다. `Library`, `Temp`, `Logs`를 옮기지 않아도 테스트 씬을 열 수 있다.
