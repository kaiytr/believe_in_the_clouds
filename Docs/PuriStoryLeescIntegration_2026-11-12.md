## 병합과 충돌 처리

Puri에서 별도 통합 워크트리를 만들고 Leesc, 1.1 순서로 일반 merge를 수행했다. 전체 파일 트리를 어느 한 브랜치로 교체하지 않았다.

- **Puri + Leesc:** Git 텍스트 충돌 0개. 런타임 소스는 공격 판정과 PC 전체 화면 시작 설정 외에는 이미 동일했다. 레벨 2의 수정된 타일·콜라이더·몬스터 설정, 제품명·아이콘·배포 설정은 Leesc 변경을 반영했다.
- Leesc의 배포용 자료 정리가 Puri의 문서·검증 캡처·개발 스크립트를 자동 삭제하려는 부분은 Puri 원본으로 복원했다. 기존 README와 이 저장소에 맞는 VS Code 솔루션 설정도 보존했다. 이 단계는 `539cd75` 병합 커밋에 기록했다.
- **이 결과 + 1.1:** 충돌은 README 1개뿐이었다. Puri의 기존 안내와 1.1의 스토리 안내를 모두 남겼다. 코드·씬·프리팹 충돌은 없었다.

## 변경 누락 검사

파일 수가 아니라 Git blob 해시를 비교했다.

- 1.1이 main에서 변경한 **75개 경로 중 README를 제외한 74개는 1.1 원본과 정확히 동일**하다. README는 양쪽 내용을 포함한다.
- Leesc가 main에서 변경한 **Player.prefab과 PlayerAttack.cs는 Leesc 원본과 정확히 동일**하다. 이 두 경로는 1.1 변경 경로와 겹치지 않는다.
- 위 두 공격 파일, 합친 README, 보존한 VS Code 설정을 제외하면 **1.1의 전체 추적 파일은 모두 통합본과 동일**하다. 최신 main과 1.1의 씬·저장·런타임 내용이 다른 과거 버전으로 되돌아가지 않았다.
- Puri가 추적하던 기존 파일 중 통합본에서 사라진 파일은 **0개**다. 기존 문서·도구·검증 자료 **103개는 Puri 원본과 동일**하며, README도 기존 안내를 포함한다.
- 기존 QoL 코드는 1.1 변경 파일에 들어간 의도된 확장 외에 Puri와 동일하다. 첫 재단 기능 때문에 저장 스키마는 명세대로 v5로 확장한다.

## 수행한 검증과 범위

Unity 6000.3.5f2의 Roslyn과 이 프로젝트의 참조 DLL로 통합 소스를 새로 컴파일했다. 이전 런타임 DLL을 통합 코드의 참조로 대체해 에디터·테스트 소스도 확인했다.

스토리 변경 에셋의 로컬 fileID·외부 GUID 연결, 신규 메타 GUID 중복, 빌드 목록의 활성 스토리 씬 등록, 병합 표시 잔존을 검사했다. 누락 참조·신규 GUID 중복·미해결 충돌은 없었다. Unity 직렬화 파일의 빈 값 뒤 공백을 제외한 Git diff 검사도 통과했다.

이번에는 EditMode·PlayMode 테스트를 실행하거나 배포 빌드를 만들지 않았다. 통합된 기능 소스와 에셋이 앞서 검증한 1.1 버전 및 Leesc 공격 수정과 일치하므로 전체 테스트를 반복하지 않았다. 이전 기능 검증은 [첫 재단 구현 결과](FirstAltarStory_ImplementationStatus.md)에 있다. 이 기록은 현재 통합본의 플레이 검수 완료나 1.1 배포 완료를 의미하지 않는다.

## 커밋되지 않은 작업

GitHub Desktop이 보관한 1.1 stash `a556706`을 발견했다. 스토리 씬·프리팹·데이터 6개 파일의 미커밋 상태이며, 요청한 브랜치 커밋과 구분해 이번 통합에는 자동 적용하지 않았다. stash 원본은 삭제하거나 변경하지 않았다. 따라서 커밋된 1.1 원본이 통합 기준이며, 미커밋 상태를 이어갈 경우 해당 stash를 별도로 검토한다.

main·Leesc·1.1의 브랜치 포인터는 그대로 보존한다. Puri만 검증한 통합 결과로 전진시키며, 이번 작업에 만든 임시 브랜치·워크트리는 통합 후 정리한다.
