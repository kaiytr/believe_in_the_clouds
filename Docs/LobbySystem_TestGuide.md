# 로비·플레이 루프 테스트 가이드

기준: Unity 6000.3.5f2. 씬 역할과 경로는 [씬 안내](SceneGuide.md)를 참고한다. 로비의 분기는 전투·상점·보스만 제공하며 각 역할의 실제 콘텐츠 씬을 사용한다.

## 시작

1. `Assets/Scenes/Gameplay/Lobby.unity`를 열고 Play한다.
2. 전체 기능을 빠르게 확인하려면 F2 패널의 **전체 플레이 루프 테스트**를 누른다. 격리된 메모리 프로필과 테스트용 100코인을 준비한다.
3. 오른쪽 분기 구역으로 이동한다. 가까운 후보에서 **E 출발**, **F 역할 공개(5코인)**다. 공개하지 않고 출발할 수도 있다.
4. 전투 분기를 완료하면 오른쪽 출구에서 E로 로비에 복귀한다. 루프 테스트의 전투 씬은 개 → 신도 → 간부 순서다.
5. 전투 사이에 상점·로비 재단을 확인한다. 전투 3회 완료 후 준비되는 보스 분기를 진행한다.

일반 신규 시작은 0코인이다. 전체 플레이 루프 테스트의 100코인은 검증용 지급이며 신규 게임 지급 규칙과 다르다.

이벤트 분기는 제공하지 않는다. 전체 플레이 루프 테스트는 보스 해금 전 전투·상점 2개, 해금 후 전투·상점·보스 3개를 보여 준다. 일반 모드의 후보 수는 기존처럼 2개 또는 3개다.

## 완료 조건

| 분기 | 완료와 복귀 |
| --- | --- |
| 전투 | 해당 씬의 적 처치 후 출구 E. 처치 전에는 복귀할 수 없음 |
| 상점 | 상점 화면을 열고 닫은 뒤 출구 E |
| 보스 | 아레나 진입 후 전투. 보스 처치 시 현재 구현의 런 완료 상태로 전환 |

보스 완료 후 정식 엔딩 콘텐츠는 후속 범위다. 다음 루프는 테스트 버튼으로 새로 시작한다.

## 테스트 도구

로비의 도구 패널은 **F2**로 표시·숨김을 전환한다. 실제 분기 안에서는 전체 플레이 루프 테스트 모드에서 도구를 사용할 수 있다.

| 버튼 | 동작 |
| --- | --- |
| 전체 플레이 루프 테스트 | 새 메모리 런·100코인·확인하기 쉬운 후보와 전투 순서 준비 |
| 새 메모리 테스트 | 빈 프로필로 새 런 시작. Play 종료 시 사라짐 |
| +100 코인 | 현재 테스트에 100코인 지급 |
| 역할 완료 | 현재 스테이지를 테스트용으로 강제 완료. 실제 처치·상점 완료 확인과 구분 |
| 피해 10 | 기존 피해·무적 처리로 10 피해 |
| 사망 | 손실 처리 성공 후 새 런·최대 HP로 로비 복귀 |
| 저장 다시 불러오기 | 같은 저장소의 런·HP·공개 상태 복원 |
| 저장 실패 켜기/끄기 | 메모리 테스트에서 실패 주입. 해제 후 사망·체력 체크포인트는 자동 재시도하고 공개·출발·완료·복귀는 다시 입력 |

## 직접 확인할 항목

| 확인 | 예상 결과 |
| --- | --- |
| 공간·조작 | 카메라 추적, 이동·점프·대시·공격, 양쪽 경계와 바닥 정상 |
| 입력 대상 | 가까운 후보 하나에 E/F가 동작. 안내가 해당 오브젝트와 카메라 이동을 따라감 |
| 공개 | F 한 번에 대상 하나의 역할 공개, 5코인 차감. 재공개 무료 |
| 부족·무료 출발 | 0~4코인에서 공개 시 차감 없음. 미공개 E 출발 가능 |
| 씬 전환 | 전투는 DogCombatTest·BelieverCombatTest·ExecutiveCombatTest, 상점은 ShopTest, 보스는 BossTest로 이동 |
| 완료 전 출구 | 전투 처치 전 귀환 거부. 완료 후 출구 사용 가능 |
| 정상 왕복 | 남은 HP 유지. 전투 클리어 수는 로비 복귀 시 한 번 증가 |
| 보스 후보 | 일반 모드에서는 전투 3회 이후 추첨 풀에 추가. 전체 루프 테스트에서는 3회 뒤 보스 후보 제공 |
| 사망 | 손실 한 번, 전투 횟수 0·새 후보·최대 HP로 로비 복귀 |
| 같은 저장 재로드 | 후보·공개 상태·HP·완료 여부 유지. 재로드만으로 클리어하지 않음 |
| 저장 실패 | 실패 중 부분 차감·씬 이동 없음. 복구 후 정상 재시도 |
| 화면비 | 16:9와 4:3에서 키 안내·HP·잔액·테스트 버튼 가독성 확인 |

## 저장과 재생성

일반 Editor Play와 위 메모리 테스트는 기본적으로 Play 종료 시 진행이 사라진다. 종료 후 이어하기는 빌드 또는 `-usePersistentEditorProfile`을 명시한 Editor에서 따로 확인한다. 지속 저장을 사용할 때도 같은 후보·스테이지·HP가 복원되고 종료만으로 클리어되지 않아야 한다.

- 지속 저장 Editor 경로: `Library/Economy/Editor/economy-save-v1.json`.
- 예전 이벤트 후보는 공개 상태를 유지한 전투 후보로 복원한다. 이벤트 스테이지에서 저장했다면 재화·남은 HP·전투 횟수를 유지한 채 로비로 돌아오고, 해당 이벤트를 전투 클리어로 집계하지 않는다.
- 빌드 저장 경로: `Application.persistentDataPath/economy-save-v1.json`.
- 보조 EconomyTest는 별도의 fixture 저장을 사용하므로 [재화 테스트 가이드](CurrencySystem_TestGuide.md)를 따른다.
- 기존 씬 실행에는 재생성이 필요하지 않다. `Tools > Lobby > Build lobby`는 로비 씬의 수동 배치를 대체한다.
