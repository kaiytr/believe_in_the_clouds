# 재화·교리 자산 시스템 상세기획

- 작성일: 2026-10-31
- 상태: **현재 범위의 게임 규칙 확정. 구현은 별도 지시 전까지 시작하지 않는다.**
- 확정 구현 범위: **재화 시스템을 테스트 씬에서 독립 검증한다. 메인 플레이 루프 연동은 나중에 진행한다.**
- 메인 플레이 루프 구현 상태: **미구현. 아래 흐름은 향후 구현할 목표 플레이 루프다.**
- 연계 문서: [개발명세서](CurrencySystem_TechnicalSpec.md), [개발자·AI 가이드](CurrencySystem_Guide.md)
- 게임 규칙은 사용자 확정 사항이며, 연출 수치는 테스트에서 조정할 초기값이다. 후속 콘텐츠 결정은 보류하고 구현은 별도 지시를 받아 진행한다.

## 1. 목적과 메인 플레이 루프

**로비 → 로비에서 분기 선택 → 스테이지 진입 → 스테이지의 역할 수행 → 로비 복귀 및 다음 분기 선택 → … → 보스 → 엔딩**

코인은 적 처치와 향후 추가될 보상 경로에서 얻고, 교리 조각 구매나 향후 추가될 소비처에서 쓴다. 자산의 기준은 보유 코인과 보유 교리 조각이다. 장착 교리는 조각을 사용해 구성한 실행 상태이며, 사망 시에는 전부 해제한 다음 보유 조각 목록에서 손실을 처리한다.

**현재 메인 플레이 루프는 아직 구현되지 않은 상태다.** 로비에서의 분기 선택, 스테이지 역할 수행 후 로비 복귀, 다음 분기 진행, 보스 이후 엔딩까지 이어지는 전체 흐름은 향후 구현 대상이다. 기존 StageTest 등은 개별 기능과 전투 통합을 검증하는 테스트 씬이다.

**이번 구현 범위는 재화 시스템을 테스트 씬에서 검증하는 것까지로 확정한다.** 코인 지급·소비, 드롭·비행·HUD, 상점 가격·결제, 코인·조각 저장, 사망 시 전체 해제 후 손실 처리를 검증한다. 초기 코인·교리·조각은 모두 지급하지 않는다.

실제 로비 생성, 분기 선택, 스테이지 역할 수행과 진행 관리, 로비 복귀, 위치·HP·적 생사를 복원하는 이어 하기, 엔딩 연동은 후속 작업이다. 테스트 어댑터가 필요한 상태와 이벤트를 제공하며, 재화 시스템 검증을 위해 메인 루프나 재단 전체를 구현하지 않는다.

게임 종료 후 자산 유지와 진행 중 스테이지에서 이어 한다는 최종 목표는 유지한다. 이번 단계에서는 코인·조각·대기 보상 저장을 검증하고, 전체 진행 복원은 향후 메인 루프 연동 시 완성한다.

| 구분 | 내용 | 상태 |
| --- | --- | --- |
| 재화 | 단일 코인, 정수 단위 | 사용자 요청 기준 |

| 초기 교리·조각 | **지급 없음. 장착 상태도 비어 있음** | 사용자 확정 |
| 개 드롭 | 5~7코인 | 사용자 확정 |

| 교리 조각 사망 손실 | **전체 장착 해제 후 보유 조각 총수의 30%, 버림, 개체별 무작위 소실** | 사용자 확정 |
| 사망 처리 순서 | **교리 전부 미장착 → 보유 조각 목록 확정 → 그 목록에서 손실** | 사용자 확정 |

| 카드 가격·등급 | 3장의 표 | 사용자 제공 이미지로 확정 |
| 이번 구현·검증 범위 | **재화 시스템만 테스트 씬에서 검증. 메인 루프 연동은 나중** | 사용자 확정 |
| 드롭 분포 | 범위 양 끝을 포함한 균등 정수 추첨 | 사용자 확정 |
| 처치 보상 자격 | 플레이어 생존 중이면 플레이어 공격·교리·환경 피해 등 출처와 무관하게 지급 | 사용자 확정 |
| 사망 효과와 보상 | 사망 효과를 한 번 실행한 뒤 전체 해제. 사망 확정 이후 처치 보상 없음 | 사용자 확정 |
| 상점 재고·반복 구매 | 무제한 재고, 장바구니에 카드당 1장, 결제 후 반복 구매 가능 | 사용자 확정 |
| 보유 상한 | 999,999,999코인, 같은 조각 종류당 9,999개 | 사용자 확정 |
| 코인 상한 초과분 | 보유·대기 합계가 상한을 넘지 않는 금액만 지급, 초과분 미지급 | 사용자 확정 |
| 화면 밖 처치 연출 | 화면 가장자리에서 HUD로 이동 | 사용자 확정, 연출 수치는 테스트에서 조정 |

시작 코인 0개와 초기 교리·조각 지급 없음은 신규 프로필을 처음 생성할 때만 적용한다. 기존 저장 불러오기, 씬 이동, 사망, 이어 하기에서는 보유 자산을 초기화하지 않는다. 테스트가 임의의 자산을 준비하는 것은 검증용 데이터이며 실제 초기 지급 규칙을 바꾸지 않는다.

## 3. 교리 상점 가격과 등급

사용자가 제공한 [가격표 원본](CurrencySystem_References/DoctrineShopPrices.png)을 그대로 적용한다. 문구는 기획 표기이며 기존 코드의 식별자도 함께 기록한다.

| 분류 | 교리 키워드 | 가격 | 등급 | 기존 식별자 |
| --- | --- | ---: | --- | --- |
| 주어 | 플레이어는 | 30 | 일반 | SubjectType.Player |
| 주어 | 일반 적은 | 30 | 일반 | SubjectType.Enemy |
| 주어 | 보스는 | 55 | 고급 | SubjectType.Boss |
| 주어 | 모든 존재는 | 95 | 희귀 | SubjectType.All |
| 조건 | 피격하면 | 55 | 고급 | ConditionType.OnHit |
| 조건 | 사망하면 | 30 | 일반 | ConditionType.OnDeath |
| 조건 | 체력이 30% 이하가 되면 | 30 | 일반 | ConditionType.LowHealth |
| 조건 | 공격하면 | 55 | 고급 | ConditionType.OnAttack |
| 결과 | 폭발한다 | 95 | 희귀 | ResultType.Explode |
| 결과 | 이동 속도가 증가한다 | 30 | 일반 | ResultType.IncreaseSpeed |
| 결과 | 공격력이 증가한다 | 55 | 고급 | ResultType.IncreaseAttack |
| 결과 | 회복한다 | 55 | 고급 | ResultType.Heal |

일반은 30, 고급은 55, 희귀는 95코인이다. 등급은 가격과 화면 표기를 위한 분류다. 등급만으로 교리 효과 수치를 변경하지 않는다. 기존 코드의 ‘피해 증가’는 ‘공격력이 증가한다’ 키워드에 대응하며, 이번 경제 기획에서 효과 공식 자체를 변경하지 않는다.

한 번의 장바구니에는 같은 카드 한 장씩을 담는다. 여러 열에서 여러 장을 선택할 수 있고 한 장만 구매해도 된다. 구매 후에는 같은 조각을 다시 살 수 있다. 재고는 무제한이다. 구매한 조각은 바로 장착되지 않고 보유 조각 목록에 들어간다. 실제 조합·장착은 후속 재단 시스템이 담당하며, 이번에는 테스트 어댑터로 장착 해제와 조각 목록 처리를 검증한다.

최소 가격의 주어·조건·결과 한 장씩을 사는 비용은 90코인이다. 이는 조합의 유효성을 보장하는 수치가 아니라 세 분류별 최저 가격의 합이다. StageTest의 개·신도·간부 각 한 마리를 처치하면 15~20코인, 균등 추첨 기준 평균 17.5코인이다. 확정된 시작 코인 0개를 기준으로, 다른 수입·소비·사망 손실이 없다면 최저가 카드 한 장은 같은 세 적 묶음 2회, 세 분류의 최저가 조각은 5~6회 수입에 해당한다. 실제 스테이지의 적 수와 보상 종류는 별도 기획이며 이 계산으로 고정하지 않는다.

## 4. 코인 드롭과 자동 획득

### 4.1 지급 조건

살아 있는 플레이어의 전투 중 적 사망이 확정되면 해당 적 종류의 드롭량을 범위 양 끝을 포함한 균등 정수 확률로 한 번 추첨한다. 사망 원인이 플레이어 공격·교리 효과·환경 피해 중 무엇인지와 관계없이 같은 보상을 지급한다. 보스는 코인을 드롭하지 않는다.

적을 비활성화하거나 오브젝트를 삭제한 것만으로는 보상을 주지 않는다. 이미 죽은 적을 다시 공격하거나 사망 알림이 중복되더라도 한 번만 지급한다. 플레이어 사망 확정 후 죽은 적의 코인 보상은 지급하지 않는다. 사망 교리 효과로 처치한 적도 이 규칙을 따른다.

이번 테스트에서는 안정적인 처치 ID로 중복 지급 방지를 검증한다. 향후 메인 루프 연동 시에는 적의 사망·보상 추첨 결과·지급 권리를 같은 진행 저장 단위로 기록해, 이어 하기에서 적과 보상이 서로 다른 시점으로 복원되지 않게 한다.

### 4.2 시각 연출

1. 적 몸체 중심 근처에서 코인 토큰이 짧게 퍼진다.
2. 토큰이 약간의 시차를 두고 곡선을 따라 우측 하단 코인 배지로 날아간다.
3. 토큰이 배지에 도착하면 해당 수량을 보유 코인으로 옮긴다.
4. 잔액 숫자가 증가하고 짧은 획득 피드백을 표시한다.

별도의 코인 오브젝트에 다가가거나 키를 누르는 행위는 없다. 토큰에는 충돌체나 줍기 범위를 만들지 않는다. 이동 중 플레이어가 움직여도 목표는 화면의 실제 HUD 위치다.

연출 테스트 초기값은 퍼짐 0.2초, 이동 0.45~0.7초, 토큰 간 시차 0.03초다. 평상시 1코인당 토큰 한 개를 사용한다. 동시 표시 초기값 64개를 초과하면 여러 코인을 한 토큰에 묶어 표현한다. 묶은 토큰 도착 시에는 표시한 실제 수량을 지급한다. 시간·크기·색상·동시 표시 수는 테스트하면서 조정하며, 수치 조정이 실제 보상량을 바꾸지는 않는다.

### 4.3 보상 권리와 표시 잔액

비행 시작 전 보상 권리를 먼저 저장한다. 아직 HUD에 도착하지 않은 금액은 ‘획득 대기’이며 구매에 사용할 수 없다. 도착한 금액만 보유 잔액에 더한다.

정상 씬 전환·사망 시에는 남은 비행을 취소하고 대기 보상을 즉시 정산한다. 정상 종료 시에도 정산한 상태를 저장한다. 강제 종료 후 대기가 남아 있으면 다음 로드에서 한 번 정산한다.

카메라나 HUD가 없어 연출을 보여줄 수 없으면 즉시 정산한다. 화면 밖에서 적이 죽으면 화면 가장자리에서 HUD로 이동한다. 비행 토큰이 사라졌다는 이유만으로 보상 권리를 삭제하지 않는다. 보유·대기 코인 합계가 999,999,999개를 넘지 않는 금액만 접수하고 실제 접수량만 표시한다. 초과분은 지급하지 않는다.

## 5. 공통 획득·소비 규칙

재화 지급·소비는 특정 적이나 상점 스크립트에 묶지 않는다. 향후 퀘스트, 이벤트, 보물상자, 스테이지 보상, 강화, 재단 비용 등도 같은 공통 진입점으로 처리한다.

| 동작 | 용도 |
| --- | --- |
| 즉시 지급 | 연출이 필요 없는 보상 |
| 연출 지급 | 지정 위치에서 HUD로 이동하는 보상 |
| 소비 | 유효한 금액을 잔액 검증 후 차감 |
| 잔액 조회·지불 가능 여부 조회 | 화면 표시와 사전 안내 |
| 원자적 구매 | 코인 소비와 교리 자산 획득을 동시에 반영 |
| 변경 알림 | HUD·상점 등 관련 화면 갱신 |

지급·소비 호출에는 사유를 남긴다. 한 번만 처리해야 하는 보상에는 거래 ID를 사용한다. 이 ID를 다시 제출해도 같은 보상을 중복 지급하지 않는다. 실패하면 코인과 관련 자산을 모두 유지하고 실패 사유를 반환한다. 잔액 조회 결과만 믿고 직접 잔액을 바꾸면 안 된다.

## 6. 상점 UX와 실패 처리

카드에는 가격과 등급을 함께 표시한다. 상점에는 보유량, 선택 수량, 결제 합계, 부족 금액을 표시한다. 잔액이 부족해도 카드 비교와 선택은 허용한다.

| 상황 | 버튼과 처리 |
| --- | --- |
| 선택 없음 | 구매 비활성, 카드 선택 안내 |
| 잔액 부족 | 구매 비활성, 부족한 코인 수 표시 |
| 구매 가능 | 구매 활성 |
| 저장 중·사망 처리 중·복원 중 | 거래를 잠그고 현재 처리 상태 안내 |
| 정상 구매 | 전체 비용 차감과 전체 조각 지급을 함께 저장, 선택 해제 |
| 저장 실패·잘못된 카드·보유 한도 | 자산 무변경, 선택 유지, 실패 안내 |

실제 구매 함수가 실행 시점에 다시 검증한다. 저장 성공 전에는 ‘구매 완료’를 표시하지 않는다. 자동 장착, 환불, 판매, 할인, 복수 재화는 이번 범위에 없다.

## 7. 사망 손실과 장착 해제

### 7.1 단일 교리 조각 목록

사망하면 교리를 전부 미장착 상태로 돌린다. 효과·구독·슬롯 연결을 정리하고, 해제 후의 **보유 교리 조각 목록 전체**를 손실 대상으로 사용한다. 사망 전 장착 여부로 조각을 분리하거나 보호하지 않는다.

장착에 사용됐던 조각도 원본 보유 조각으로서 같은 목록에서 정확히 한 번 센다. 장착 해제 때문에 새 조각을 중복 지급하지 않는다. 별도의 완성 교리 보관함이나 완성 교리 단위의 추가 손실은 이 시스템에 만들지 않는다.

### 7.2 손실 계산

- 코인 손실: floor((보유 코인 + 비행 중 대기 코인) × 30 / 100).
- 조각 손실: **floor(전체 장착 해제 후 보유 조각 총수 × 30 / 100)**.
- 조각은 개체별 동일 확률로, 손실 수만큼 비복원 무작위 추출한다.

주어·조건·결과 등 종류마다 따로 30%를 계산하지 않는다. 장착 교리 개수로 별도 손실을 계산하지 않는다.

예시에서 교리 한 개는 주어·조건·결과 각 한 조각으로 구성한다.

| 사망 직전 상태 | 해제 후 손실 기준 | 소실 | 결과 |
| --- | --- | --- | --- |
| 19코인 + 비행 중 3코인 | 총 22코인 | 6코인 | 16코인 |
| 미장착 조각 7개 | 총 7조각 | 무작위 2조각 | 5조각, 장착 없음 |
| 장착 교리 3개에 사용된 9조각, 그 외 조각 없음 | 총 9조각 | 무작위 2조각 | 7조각, 장착 없음 |
| 미장착 조각 7개 + 장착 교리 2개에 사용된 6조각 | 총 13조각 | 무작위 3조각 | 10조각, 장착 없음 |

### 7.3 처리 순서

1. 사망을 확정하고 신규 거래와 비행 도착 처리를 잠근다.
2. 기존 사망 교리 효과를 한 번 실행한다. 이 효과를 포함해 사망 확정 이후 발생한 적 처치에는 코인 보상을 지급하지 않는다.
3. **교리를 전부 미장착 상태로 돌리고, 구독·지속 능력치 효과·장착 UI 연결을 정리한다.**
4. 원본 보유 조각을 중복 없이 정규화한 전체 조각 목록을 확정한다.
5. 그 목록의 총수에서 30%를 버림해 소실 수를 계산하고 무작위 조각을 선정한다.
6. 대기 코인을 정산한 코인 손실과 조각 손실, 전체 미장착 상태를 하나의 사망 거래로 저장한다.
7. 테스트 씬에서는 결과와 해제 상태를 확인한다. 실제 로비 복귀는 후속 메인 루프에서 연결한다.

저장 실패 시 부분 손실 결과를 공개하지 않는다. 같은 사망을 재시도해도 조각 반환이나 해제가 반복 누적되지 않고, 최초 선정한 손실 결과를 사용한다. 같은 사망 알림은 한 번만 처리한다.

처리 후에는 남은 조각만 보유하며 장착은 비어 있다. 손실로 일부 조각이 사라진 과거 교리 조합을 자동 복원하지 않는다. 정상 씬 이동·일시정지·스테이지 완료는 사망 손실을 발생시키지 않는다.

## 8. 저장과 향후 이어 하기 연동

### 8.1 이번 범위: 경제 자산 저장

보유 코인, 획득 대기 보상, 보유 조각 수량, 처리 완료 거래 ID, 사망 손실 처리 상태를 함께 저장한다. 장착 해제와 손실은 테스트 어댑터를 통해 검증하고, 처리 후 장착 없음과 남은 조각 목록이 일치해야 한다.

신규 프로필은 0코인·0조각·장착 없음으로 만든다. 기존 프로필은 저장 자산을 그대로 복원한다. 테스트 씬 재진입과 저장 재실행에서 대기 보상 누락·중복 지급·중복 사망 차감이 없는지 확인한다.

JSON 임시 파일 기록 후 본 파일을 교체하고 직전 정상본을 백업한다. 본 파일이 손상되면 검증한 백업으로 복구한다. 유효한 파일이 전혀 없으면 변경을 잠그고 오류를 표시한다. 손상 파일을 빈 신규 프로필로 자동 덮어쓰지 않는다.

### 8.2 후속 범위: 메인 루프 진행 복원

최종 게임에서는 정상 종료 후 마지막 위치·HP·적 생사·획득 보상을 함께 복원해 진행 중 스테이지에서 이어 한다. 이를 위해 경제 자산과 진행 상태를 같은 시점의 저장 단위로 결합한다.

후속 진행 데이터에는 스테이지·분기 ID, 플레이어 위치·HP, 적 스폰 ID·생사·HP·위치와 처치 보상 ID, 역할 수행 상태, 장착과 원본 조각의 연결을 포함한다. 사망이 확정된 진행은 손실 결과가 적용된 자산으로 로비에 복귀한다.

이번 재화 검증에서는 실제 로비·분기·진행 관리·전체 스테이지 복원기를 개발하지 않는다. 필요한 연결 계약과 테스트 어댑터만 둔다. 복원 시 공격·투사체 처리, 보스 페이즈와 지속 효과는 후속 전투/진행 시스템과 연계한다.

## 9. 확정 구현 범위와 검수 기준

후속 구현 지시를 받은 뒤의 범위는 **재화 시스템을 테스트 씬에서 독립 검증하는 것**이다.

| 이번 검증에 포함 | 후속 메인 루프 연동에서 구현 |
| --- | --- |
| 공통 지급·소비 API, 잔액 검증, 거래 저장 | 실제 로비·분기 선택·스테이지 진행 |
| 지정 드롭, 퍼짐·비행·HUD 도착 증액 | 스테이지 역할 수행과 엔딩 |
| 확정 카드 가격·등급과 결제 | 재단 전체 조합·장착 UI |
| 코인·조각·대기 보상 저장·복원 | 위치·HP·적 생사를 포함한 전체 이어 하기 |
| 테스트 장착 어댑터의 일괄 해제와 조각 손실 | 실제 장착/재단 시스템과 어댑터 연결 |
| 테스트 씬 내 사망 결과와 중복 방지 | 실제 사망 로비 복귀 |

검수 기준:

- 신규 시작은 0코인·0조각·장착 없음이다.
- 지정 드롭 수량과 가격·등급이 일치한다.
- 접근이나 줍기 입력 없이 드롭·비행·도착 증액이 동작한다.
- 비행 중 사망·씬 이동·종료에도 누락과 중복이 없다.
- 다른 기능이 공통 API만으로 지급·소비할 수 있다.
- 잔액 부족·저장 실패·중복 거래에서 자산이 잘못 변경되지 않는다.
- 사망 시 전체 장착 해제와 효과 정리가 손실보다 먼저 이뤄진다.
- 해제 후 보유 조각 전체 목록을 기준으로 30%를 버림해 손실을 계산한다.
- 장착 여부에 따른 손실 예외, 조각 중복 반환, 별도 완성 교리 소실이 없다.
- 재실행 후 남은 코인·조각·대기 보상과 사망 처리 결과가 일치한다.
- 메인 루프 연동이 아직 미구현임을 구현 결과서에도 명시한다.

## 10. 규칙 확정과 후속 검토

### 10.1 현재 검증 범위의 게임 규칙 확정 완료

이전에 미확정으로 정리했던 사항은 현재 제안대로 사용자 확정됐다.

| 항목 | 확정 내용 |
| --- | --- |
| P03 사망 효과·처치 보상 | 사망 효과를 한 번 실행한 뒤 전체 해제. 사망 확정 이후 적 처치 보상 없음 |
| P04 재고·반복 구매 | 무제한 재고, 같은 장바구니에 카드당 1장, 결제 후 반복 구매 가능 |
| 드롭 확률 | 각 범위의 양 끝을 포함한 균등 정수 추첨 |
| 환경 피해 등 처치 보상 | 플레이어 생존 중이면 피해 출처와 관계없이 지급 |
| 보유 한도·초과분 | 999,999,999코인, 조각 종류당 9,999개. 코인은 상한 이내 금액만 지급 |
| 화면 밖 처치 | 화면 가장자리에서 HUD로 비행 |

**현재 테스트 씬 재화 검증 범위에서 추가로 확정해야 할 게임 규칙은 없다.** 초기 지급 없음, 전체 해제 후 단일 조각 목록에서 손실, 메인 루프 후속 연동 범위도 그대로 유지한다.

### 10.2 테스트에서 조정할 연출 초기값

퍼짐 0.2초, 이동 0.45~0.7초, 토큰 시차 0.03초, 동시 표시 64개로 테스트를 시작한다. 시간·크기·색상·표시 수는 테스트 결과에 따라 조정하도록 설정으로 분리한다. 금융상의 지급량·상한·손실률은 연출 수치와 구분한다.

### 10.3 후속 콘텐츠 결정 보류

다음 항목은 이번 범위에서 결정하거나 구현하지 않는다.

- 엔딩 이후 새 플레이의 자산 초기화·계승 규칙.
- 실제 스테이지 적 수·보상 구성과 첫 구매/첫 조합까지의 목표 시간.
- 메인 루프의 진행 복원·로비 전환과 재단 연결의 구체 설계.

**게임 규칙 확정은 구현 시작 지시가 아니다. 별도 지시 전에는 구현을 시작하지 않는다.**
