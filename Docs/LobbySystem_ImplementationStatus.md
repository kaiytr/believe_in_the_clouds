# 로비·임시 스테이지 구현 결과

작업일: **2026-11-01 (Asia/Seoul)** · Unity **6000.3.5f2**

[로비 상세기획](LobbySystem_Design.md)에 따라 로비 선택과 임시 스테이지 왕복을 연결했다. 직접 플레이할 항목과 조작법은 [테스트 가이드](LobbySystem_TestGuide.md)에 있다.

## 구현

| 영역 | 현재 동작 |
| --- | --- |
| 씬 | `Lobby.unity` / `TemporaryStage.unity`. 기존 Player·PlayerHud 프리팹 사용. 빌드 시작은 Lobby, 기존 등록 씬 유지 |
| 공간 | 가로로 긴 안전 로비, 바닥과 양쪽 경계, 플레이어 추적 카메라, 향후 재단 배치 공간 |
| 분기 | 큰 사각형 trigger. 캐릭터가 앞에 보이고 통과 가능. 겹침만으로 동작 없음 |
| 입력 | 기존 가장 가까운 상호작용 대상 공유. E 출발, 선택적 `ISecondaryInteractable` F 보조 동작. 모달 중 둘 다 차단 |
| 공개 | 기본 회색·`?`, 선택 대상만 5코인으로 역할명·색상 공개. 재공개 추가 차감 없음, 미공개 무료 출발 |
| 후보 | 2/3 각 50%, 일반 전투 1개 보장. 나머지 허용 역할 동일 가중치, 전투만 중복, 위치 섞기 |
| 보스 | 현재 런 전투 3회 정상 복귀 후 추첨 풀에 추가. 최대 1개, 기본 비공개·공개 5코인, 전투 보장 유지 |
| 스테이지 | 선택한 역할·완료 여부 표시. 테스트 완료/피해/사망, 완료 전 출구 차단. 메뉴 중도 귀환 없음 |
| 정상 복귀 | 완료 후 출구 E. 남은 HP·자산 유지, 새 후보 생성. 전투만 1회 증가, 중복 완료/복귀는 추가 집계 없음 |
| 사망 | 기존 사망 효과·전체 해제·30% 손실 뒤 새 런·전투 0·새 후보·보스 잠금·최대 HP로 로비 복귀 |
| 이어하기 | 런 ID·생명 ID·후보 ID/역할/배치/공개·영역·선택 스테이지/완료·HP/위치·재화를 함께 복원 |
| 검증 도구 | F2 패널, 빈 메모리 프로필·코인 지급·완료·피해·사망·저장 재로드·격리된 저장 실패 주입 |
| 임시 보스 완료 | 저장되는 런 완료 표시에서 정지. 정식 보스·엔딩 연출/이후 정책은 후속 |

후보 오브젝트는 커밋된 데이터에서 실행 중 생성하므로 Editor의 정지 화면에는 표시되지 않는다. 씬 생성 메뉴는 `Tools > Lobby > Build lobby and temporary stage`이며 수동 배치를 교체하므로 재생성할 때만 사용한다.

## 저장과 재시도

기존 경제 프로필을 **schemaVersion 2**로 확장했다. 저장 파일명 `economy-save-v1.json`과 기존 경로는 유지한다. v1은 코인·조각·거래 결과·사망 저널을 보존하면서 런 정보가 없는 v2로 읽고, 처음 로비에 들어올 때 런만 추가한다. Invalid/FutureVersion은 기존과 같이 보존·잠금한다.

- `hasRun` / `hasStage`로 Unity JSON의 인라인 null 직렬화를 구분하고 로드 시 정규화한다.
- `EconomyService`의 partial 구현에 런 트랜잭션을 추가했다. 공개 차감/플래그, 선택/영역 변경, 복귀/클리어 수/새 후보는 기존 **복사 → 검증 → 저장 → 게시** 경로를 공유한다.
- 사망 결과와 새 런은 기존 사망 저널의 최종 커밋에서 함께 저장한다. 저장 실패 중에는 조작·이동을 잠그고 기존 저널로 재시도한다.
- 완료·복귀·공개·출발은 후보/스테이지 ID별 최초 결과를 영속 기록한다. 중복 호출이 횟수나 비용을 재적용하지 않는다.
- 다음 후보 추첨 시드는 완료한 스테이지 ID에서 결정한다. 복귀 저장 실패 후 프로세스를 재시작해도 같은 다음 후보가 된다. 사망 새 런도 기존 사망 ID·저장된 시드로 결정한다.
- 체력 변경은 즉시 체크포인트를 시도한다. 위치는 0.75초 간격과 일시 정지/종료 시 저장한다. 체크포인트 실패는 조작을 잠그고 0.5초 간격으로 재시도하며 거래 영수증을 계속 늘리지 않는다.
- 씬 이동은 저장 성공 후 시작한다. 다시 시작할 때 열었던 씬과 저장 영역이 다르면 저장 영역으로 이동한다. 전환 직전 입력은 다음 씬에서 바로 재사용하지 않는다.
- 씬 전환 전 비행 예약을 같은 저장에서 정산하며 늦은 코인 도착 콜백은 중복 지급하지 않는다.

주요 코드: `Assets/Scripts/Lobby/`의 데이터/규칙·경제 partial·라우터·씬 뷰·분기·출구·카메라. `PlayerHealth.HealthChanged`와 `RestoreHealth`, `PlayerDeathCoordinator.BindRunLife`로 체력과 사망 ID를 연결했다.

## 검증

자동 테스트는 열린 원본 Unity를 조작하지 않고 `.utmp/lobby-verification` 프로젝트 복사본에서 실행했다. 실제 사용자 디스크 프로필 대신 메모리/임시 저장소를 사용한다.

| 실행 | 전체 | 로비 전용 | 결과 |
| --- | --- | --- | --- |
| 전체 EditMode | 121 | 25 | 전부 통과, 실패/스킵 0 |
| 전체 PlayMode (그래픽 켬) | 75 | 7 | 전부 통과, 실패/스킵 0 |

총 **196개**의 서로 다른 테스트가 통과했다. 기존 교리·믿음·보스·상호작용·재화·StageIntegration도 포함한다. 저장 버전 이전 테스트의 fixture를 수정한 뒤 EditMode 전체를 다시 실행했다. 마지막 씬 전환 중 종료 체크포인트 보완 이후 로비 PlayMode 7개도 다시 실행해 전부 통과했다.

로비 전용 자동 검증은 후보 생성/보스 조건, 0·4·5코인 경계, 공개 원자성/중복 방지, 미공개 출발, 출발/완료/복귀 저장 실패, HP·완료 상태 재로드, 중도 귀환 차단, 전투 집계, 저장된 사망 저널 재개/손실 한 번, 새 런·최대 HP, 기존 v1 마이그레이션, 전환 중 종료, trigger·정렬·추적 카메라·메모리 도구를 포함한다.

16:9/4:3 미공개/공개 화면과 완료된 임시 스테이지를 자동 캡처했다. XML·로그·캡처는 로컬 `Logs/LobbyVerification/`에 모으며 Git에는 포함하지 않는다.

수동 플레이 검증은 사용자가 직접 진행할 항목으로 남긴다. UI 조작감·사각형 간격·화면 가독성·카메라 속도는 테스트 가이드에 따라 확인한다.

## 후속 범위

- 실제 전투 클리어 신호, 실제 상점 이용 완료, 이벤트 결과를 임시 완료 버튼 대신 연결.
- 재단 시설과 실제 장착 조합의 정상 씬 전환 유지·전체 저장 복원.
- 정식 보스 전투, 엔딩과 엔딩 이후 자산/런 정책.
- 실제 적·환경·드롭 등 전투 월드 전체 이어하기.
- 최종 아트·음향·연출과 카메라/크기/간격 조정.

이번 구현은 장착 조합이나 실제 전투 월드의 복원 완료를 뜻하지 않는다. 코인·원본 조각·임시 런 상태가 연결된 첫 플레이 루프 범위다.
